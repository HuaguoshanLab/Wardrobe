# 后端 AI 开发约定

适用于 `backend/`。先读取并遵守 [根 AGENTS](../AGENTS.md)。

## 结构与依赖

- 技术版本、模块边界以 [ARCHITECTURE](../ARCHITECTURE.md) 为准。Python 固定 3.13，用 uv 锁定依赖。
- 路由处理 HTTP，service 处理业务，repository 处理数据库；Agent 工具调用业务服务，不绕开业务校验直接修改表。
- PostgreSQL 是业务事实来源。SQLAlchemy Session 不跨并发任务共享，不在长时间模型请求中持有数据库写事务。
- 表结构变更使用 Alembic。不要在普通启动时用 `create_all()` 代替迁移，也不要让每个 worker 并发执行迁移。
- Checkpointer 表由对应适配器管理，使用独立 schema 与明确的初始化/升级步骤，不与 Alembic 的业务表所有权混淆。
- 普通偏好保存在业务表；pgvector 仅预留，Mem0 不引入。

## 文件与依赖边界

- 执行根 AGENTS 的文件规模规则。每层按业务域拆文件，不把全部模型放进 `models.py`、全部接口放进 `routes.py`、全部工作流放进 `agent.py`。
- 一次请求的路由、schema、service、repository 可以分层协作，但不为没有独立职责的代码制造转发层；小而内聚的实现可以保持在一起。
- LangGraph 的 `graph.py` 只组装节点和边；状态、节点、工具、提示模板及 provider 各有明确位置。复杂节点按执行步骤/职责拆分，不仅按行号截断。
- API 和 worker 调用 service/Agent；service 调用领域规则、repository 或 provider；领域规则不依赖 FastAPI、具体数据库或模型 SDK，repository/provider 不反向导入路由或整张图。
- 图片解码、去背景、Excel 图片匹配与备份恢复不是一个 `file_utils.py`。分别组织，复用明确的媒体存储接口。
- schema、模型和测试按同一业务领域命名以便定位；跨模块变更按依赖路径检查，不为了“模块化”复制实体或硬约束规则。

## 模型与业务约束

- 模型返回值一律经 Pydantic 和领域校验：真实单品 ID、可用状态、锁定单品、最多三套、有区别、未拥有建议独立标识。
- 对用户输入、图片内文字、标签、Excel 内容和天气返回值保持数据边界，不允许其改变系统规则或触发任意文件/网络操作。
- 每次运行设置超时、有限调用步数和修正次数；记下模型配置版本与结果来源，不无限重试。
- 核实实际百炼地域、模型输出格式与工具调用能力；未验证前不假定全部兼容特性可用。按结构化动作编排的降级路径不能越过权限和业务约束。
- 调整只产生新的不可变搭配版本，不修改历史快照。提交新版本前重新检查已删除或不可用衣服。
- 锁定与可用性冲突按契约返回阻塞原因，由用户调整，不私自改变任何一项。

## 任务与恢复

- API 创建持久化任务，worker 执行，SSE 读取事件；请求连接不是任务生命周期。
- 幂等键绑定请求内容，重复同请求返回原任务；同键不同内容报冲突。
- 图检查点、任务状态、SSE 序号分别管理。记录请求与调用状态，不能声称任意模型服务具有 exactly-once 保证。
- 浏览器重连不得重新调用模型；进程崩溃后遇到外部请求结果不明，标为中断/待确认，不盲目重发付费请求。
- 普通 Job 终态、结果与最终事件同事务提交；恢复控制任务按独立持久记录推进。Checkpointer 独立提交，节点重放先读业务提交标记及步骤响应。模型重试总预算、取消竞争和 outbox/租约语义按 CONTRACTS 实现，不靠库默认行为推测。
- 图片转换、去背景和 Excel 解析不阻塞 API 事件循环。具体任务队列经验证后记录 ADR，不再默认使用旧 SQLite 队列方案。
- 不在日志、事件或异常响应中暴露密钥、完整照片、私钥和敏感提示内容。

## 文件与数据

- 使用真实解码、大小及像素限制验证图片；保留原件，生成方向正确、剥离元数据的标准衍生图；向云端发送必要的衍生图。
- Excel 只支持固定版本 `.xlsx` 模板。按锚点匹配嵌入图，不靠图片在 ZIP 内的顺序。拒绝宏和外链执行，不求值公式；错误定位到行。
- 导入确认与正式衣服创建需事务和行级幂等；重复确认不重复入库。
- 行确认采用逐行事务/保存点及版本检查；后台识别按 touched_fields 合并，不能覆盖人工编辑。通用 Job 结果按 kind 区分，导入和备份任务不返回虚假的 revision_ids。
- 文件路径由服务生成，不直接使用用户文件名拼接存储路径。校验解压路径、大小和图片资源范围。
- 删除衣服不删除历史引用的图片；文件清理必须检查所有业务和快照引用。
- 备份保持数据库与图片一致；恢复先校验并要求用户确认覆盖，失败可回退。恢复后不自动执行备份中的旧任务。
- 维护态覆盖 API、worker、检查点和文件清理；恢复控制状态不能只存进将被覆盖的业务数据库。按 ARCHITECTURE 的完整顺序实现与验证。

## 验证与文档

- PostgreSQL 特有逻辑、Alembic 和 Checkpointer 集成用 PostgreSQL 测试，不用 SQLite 假装等价。
- Fake Provider 需要覆盖结构错误、非法衣服 ID、不可用/锁定冲突、超时和中断；其结果不得冒充真实模型。
- 修改公开 schema 同时更新 OpenAPI 导出、前端类型与契约测试。
- 更新 [后端 README](README.md) 的实际命令和 [DEVELOPMENT](../docs/DEVELOPMENT.md) 的验证结果，未知或未跑的检查如实说明。
