## 任务调度决策（D-09）

选择直接由 PostgreSQL Job 表可靠领取，使用 `FOR UPDATE SKIP LOCKED`；API 事务内创建 Job 和初始事件，提交后即成为可领取任务，因此不需要第二套 broker 或另一个 outbox。依据是项目首版单人、低并发，PostgreSQL 已是必需依赖。

Celery/RQ 一类 broker 方案会增加 Redis/RabbitMQ 及双写协调；通用 PostgreSQL 队列库也是可选方案，但当前只有少量明确 Job 类型，直接领取足以验证基本语义。没有做吞吐量基准，不宣称适合高并发调度。未来若加入优先级、定时任务或大规模并发，再基于证据评估队列库，业务状态语义保持不变。

- 首版 worker 串行执行诊断，每 0.5 秒轮询；领取时生成 token，30 秒租约，每 10 秒心跳；过期 token 不可续租或提交。
- 失联任务转 interrupted，不自动重发；用户重试创建关联旧 Job 的新任务。取消先提交则晚到结果不能成功保存。
- Fake 请求发送前记录 call_state，响应持久化后才推进检查点；恢复时复用响应。sent 但结果未知时中断，不盲目调用。
- 结果、终态及最终事件同事务提交；Checkpointer 独立保存，不提供外部请求 exactly-once 保证。
- 业务事件默认保留 7 天，worker 清理过期事件；最终 Job/result 和幂等记录不自动清理。
- P1 只支持 `diagnostic` Job，不创建假穿搭、衣服或导入结果；P2/P4 需要新增按类型区分的输入/结果 schema。

依据：[PostgreSQL 行锁与 SKIP LOCKED](https://www.postgresql.org/docs/18/sql-select.html)、[官方 Postgres Checkpointer 用法](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint-postgres/README.md)。

## 可调用接口

全部以 `/api/v1` 为前缀。实际结构见 [OpenAPI](../backend/openapi.json)。

| 接口 | 行为 |
|---|---|
| GET `/health/live` | 无数据库依赖的存活检查 |
| GET `/health/ready` | 数据库、业务 revision 和检查点设施就绪 |
| GET `/capabilities` | provider_mode、未实现能力、data_epoch；不调用模型 |
| POST `/diagnostics/jobs` | 仅显式 Fake；message、delay_seconds（0–15）、scenario（success/failure）；要求幂等键 |
| GET `/jobs/{id}` | 只读任务与结果 |
| GET `/jobs/{id}/events` | SSE；after_seq/Last-Event-ID；终态返回完即关闭 |
| POST `/jobs/{id}/cancel` | 排队直接取消；执行中请求取消；终态幂等 |
| POST `/jobs/{id}/retry` | 失败/中断后显式创建新任务；要求新动作幂等键 |

首个诊断结果为 `{provider_mode: "fake", message: "…"}`。诊断输入中的 delay/scenario 只用于工程验证，不是正式搭配 API 的字段。

## 工具版本与兼容处理

运行基线：Node 24.19.0、Python 3.13.14、PostgreSQL 18.4、uv 0.12.7、Nginx 1.28.2。镜像固定标签；包的完整传递依赖精确版本分别以 [package-lock.json](../frontend/package-lock.json) 和 [uv.lock](../backend/uv.lock) 为准。

应用使用 TypeScript 6。当前 openapi-typescript 7.13.0 的 peer dependency 要求 TS 5，因此将生成器置于 `frontend/tools/openapi` npm workspace，单独依赖 TS 5.9.3，仅构建生成声明；应用编译器仍为 TS 6，共用一个 npm 锁文件。不使用 force/legacy-peer-deps。

诊断工具通过 lazy import 加载；手机 HTTP 不依赖仅安全上下文可用的 randomUUID，操作键使用 getRandomValues。CSS 按外壳、页面、响应式职责拆分，不压缩源文件规避规模检查。
