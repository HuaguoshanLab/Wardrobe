# 2026-10-30 · P7.2 穿搭轮换

用户要求按新版 P7 计划继续实现 P7.2、完整验证后部署、保留现有数据并同步记录。行为和字段单点维护在 [P7.2](../P7-2.md)。本记录区分工程、真实模型和部署证据。

## 实现

- 条件页增加正常推荐、尽量避开近期组合、优先近期少穿；兼容旧会话/草稿，保留城市切换与复用的条件，过期天气仍重新核对。
- 实际穿着聚合读取 7/30 个本地自然日内所有 WearRecord，包含手动和 AI；同单品同日去重，完整组合和主体组合按真实 ID 集合比较。
- 提交事务冻结统计；重发、恢复和查询沿用快照，后续补记/改日/删除只影响新提交。已删除衣服的历史仍在统计中，但不能回到候选。
- 后端硬约束校验后按条件未满足项、重复/记录天数稳定排序；结果卡片和历史详情显示冻结依据。不根据“0 天”推断从未穿过，不用鞋包变化冒充主体轮换。
- 模型摘要有界，完整数据留在任务；无新增数据库迁移或生成循环。新备份版本为 0.7.2-rotation，仍采用精确版本匹配，旧包在对应旧版本恢复。

## 真实千问对照

固定合成衣橱为白/蓝两件上衣、黑/灰两条裤子和白鞋，均具备相同的日常/休闲/春秋已记录属性；白上衣、黑裤和白鞋近 30 天记录 8 天，蓝上衣和灰裤期间无记录，最近 7 天记录原组合。没有读取或上传用户照片，也没有写入生产衣橱、穿着或业务任务。

通过实际 Qwen 适配器调用 qwen3-vl-plus，结果经过同一 Pydantic 和后端领域校验/排序。脚本固定预算，不自动重复。最终 `outfits-v5.2-rotation` 的四个样例均通过：

| 场景 | 最终首套 | 核对 |
|---|---|---|
| 正常推荐 | 白上衣 + 黑裤 + 白鞋 | 正常可返回已穿组合 |
| 避开近期 | 蓝上衣 + 灰裤 + 白鞋 | 主体未出现在近期记录中，鞋可复用 |
| 完整组合锁定 | 白上衣 + 黑裤 + 白鞋，仅一套 | 全部锁定保持，说明近期重复 |
| 优先少穿 | 蓝上衣 + 灰裤 + 白鞋 | 两件期间 0 天记录的主体排在首位 |

两次早期失败均为模型第一套正确保留锁定，但第二/三套为了多样性漏掉锁定项，被后端整体拒绝。v5.1 单列 required/excluded ID 后仍出现；v5.2 将仅含后端 UUID 的硬约束放入系统规则，并明确完整组合锁定时可只返回一套，最终通过。没有删除非法候选后冒充成功，没有放宽锁定规则。

本轮总计 **10 次真实调用**：v5 三次（2 通过/1 拒绝），v5.1 三次（2 通过/1 拒绝），v5.2 四次（全部通过）。最终每例各一次，轮换没有额外修正调用。模型可能仍失败，应用保留原有有限纠错和明确失败机制；这是固定小样本，不是通用推荐质量保证。适配器验收没有创建生产 ModelCall 账本；计数来自受控脚本调用，原始响应和结果在本地私有证据中。v5 的失败响应未在校验前落盘，保留调用脚本、退出日志与拒绝原因；v5.1 起在校验前保存原始响应。
