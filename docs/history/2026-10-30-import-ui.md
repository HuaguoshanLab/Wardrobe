# 2026-10-30 导入全流程界面与交互优化

用户要求优化表格导入、照片识别到确认入库的整条流程，做完一项验证一项。本轮按上传 → 审核 → 编辑 → 确认顺序实施，保留 [导入契约](../IMPORT-DETAILS.md) 和此前 [流程修复](2026-10-30-import-flow-audit.md) 的行为。已部署本地 Web，未提交 Git。

## 设计与交互

1. **上传入口**：保留暖白与深绿，方式选择改为紧凑文字卡片；照片先选文件，格式限制折叠，识别服务说明保持可见；Excel 先下载模板、按行填写，再上传检查。上次审核入口提前；提交区显示已选数量和下一步，未选择文件说明原因。文件预览、追加/移除、切换保护及原上传重试保持。
2. **识别与审核**：上传与审核共用步骤指示；总件数并入标题，分类计数直接放进筛选，移除重复统计块。处理中展示实际步骤完成数量，Excel 不展示照片属性识别步骤，不使用模拟百分比。手机采用单件卡片，图片、分类、疑点、状态和操作分组；选中项有底色反馈。源文件错误直接显示重传入口，批量栏显示当前选中数量。
3. **逐件修改**：错误字段集中提前，重置后需明确保存；提供分类/状况、获得/收纳、外观/场景分组直达按钮，键盘焦点随之移动。缩小表单容器间距，窄屏日期和金额不挤压；金额等校验错误会聚焦对应输入并滚动到可见位置。保留人工填写优先、后台轮询不覆盖草稿、改品类清子类、继续编辑下一件及固定保存栏。
4. **确认入库**：列表显示图片、名称、品类、子类、季节和可穿状态，识别提醒可展开。确认与继续核对固定在面板底部，长批次和横屏不用滚到底部找按钮。正在提交与结果不明分别显示；原请求恢复、同键重试、版本检查和部分失败处理保持。

使用项目 `ui-ux-pro-max` 技能；检索 `progressive disclosure form review` 的提交反馈、标签与标题换行建议，并参考可访问性、触摸尺寸及焦点避让检查。沿用已有视觉规范和公共 Sheet/SheetFooter，未新增依赖、主题或模型调用。
