# 2026-10-29 · W4 界面与交互优化

用户要求优化 W4 换季整理的设计与交互。范围限 W4 前端，不修改后端契约、迁移、数据模型或已有 W1～W4 业务规则；保留先前未提交修改。

## 已实现

- 记录页分为未完成整理与折叠历史，显示真实范围、日期和当前步骤；分页数量明确已加载口径。
- 会话顶部显示实际核对进度、变化及待办数量，四步导航配合明确的下一步入口。未保存草稿禁止刷新和切步，离开可继续编辑。
- 核对页增加名称/待办搜索、带数量分组、独立核对状态。搜索与分组写入 URL，刷新、保存及切步后保留；修复快速切换分组并搜索时参数相互覆盖的问题。
- 处理页可筛选待办、最近未成功及已选单品，跨分组保留选择。动作按继续持有/退出分组，确认对象与具体动作移到独立底部面板，固定执行和返回按钮；返回保留表单，再次打开重新确认。
- 批量结果明确反馈成功/失败项数；动作记录倒序、显示具体动作，最近失败项可单独筛选。总结超过五条遗留项可展开，过期核对/未确认目标可直接返回对应步骤。
- 保留明确执行、退出全季影响、版本校验、原请求重发及冻结总结。前端查询不调用模型，不隐式执行整理动作。

视觉沿用暖白/深绿、系统字体、Lucide 和 Base UI，减少重复容器、突出单品及操作层级。使用项目 ui-ux-pro-max；检索 `multi step progress recovery --domain ux` 命中进度与错误恢复，`list search filtering --stack react` 命中延迟筛选；读取 quick-reference 与 pro-rules，按本项目采用实际进度、明确结果、搜索筛选和语义控件。没有引入字体、图片或动画依赖。样式按页面布局、表单和流程交互拆分，详细行为见 [W4](../W4.md#界面与操作)。
