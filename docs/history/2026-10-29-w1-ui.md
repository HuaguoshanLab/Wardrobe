# 2026-10-29 · W1 生命周期界面与交互优化

用户要求优化 W1 的设计和交互。本轮只调整已实现的生命周期体验，不进入 W2、不改数据库或生命周期 HTTP 契约。

## 已完成

- 页面按当前状态、日常管理、单品档案、时间线、归档入口组织。真实图片提供失败占位与重试；可穿状态和收纳状态分开，穿着天数只显示真实记录。
- 日常管理四个入口直接显示当前值；维修独立成行。退出入口位于页尾、二次确认保留，已退出档案提供撤销并可展开查看保留的状态资料。
- 可穿、存放、整理决定使用原生单选控件。普通操作的日期和可选说明折叠；退出、撤销、更正默认展开。完成维修表单不再提供后端明确禁止的状况和维修原因选项。
- 新增子类移到获得资料表单中，创建成功自动选中，保存档案才关联单品；放弃子类草稿不会丢失父表单输入。查询失败保留当前子类选择，支持重试。
- 时间线显示发生日期、动作、主要变化和已填写的说明；完整前后差异、保存时间、版本和更正入口收进“详情与更正”。不在普通展示中暴露子类 UUID；原事件不可变、更正不改当前状态。
- 单品详情增加明确的生命周期入口；返回详情和衣橱继续携带原筛选来源。弹层关闭恢复入口焦点，浏览器返回保留逐层关闭与草稿确认。
- 展示组件与表单样式按职责拆分，保留共享版本、幂等重发、失败草稿和退出确认机制。

## 设计依据

读取项目 `ui-ux-pro-max` 技能与现有 [界面约定](../design/UI.md)。两次操作层级检索没有得到可验证的直接匹配，采用技能 quick-reference 的 primary-action、progressive-disclosure、触控与可访问性通用规则；不把无关搜索结果作为设计依据。延续暖白、深绿、Lucide 和公共底部面板，不引入依赖、字体服务或另一套主题。

## 验证

- Node 24：完整组件测试 58 项通过，包含新增的子类草稿独立放弃、创建后自动选择及维修合法选项验证。最终相关组件 11 项复验通过；类型检查、格式和生产构建通过。
- 浏览器：W1 UI 六项（桌面与 Pixel 7）及隔离 Fake 完整流程两项。检查打开/刷新/关闭零写入、草稿保留、子面板浏览器返回、焦点恢复、长表单保存按钮完整可见、长名称、图片失败、归档与时间线展开。另检查 320/375px、844×390 横屏、减弱动画与 CSS 200% 放大无横向溢出。
- 一次新组件断言将 number 输入经浏览器规范化后的 `39.9` 错当作 `39.90`，修正断言后通过；原金额仍作为字符串发送，不在客户端转换浮点数。
- 一次浏览器测试在确认面板退出动画结束前查询关闭按钮，出现两个匹配；增加等待确认面板卸载，保留动画与原交互。
- 扩大可访问名称后，测试的模糊 label 同时匹配了背景入口和输入框，改为精确 textbox 定位；200% 放大检查发现历史网格最小宽度撑出页面，修正主网格可收缩轨道、手机差异纵向排列及归档区域换行后定向通过。
- 完整流程只在 `wardrobe-p6-regression` 独立数据库/媒体卷、Fake Provider、内网隔离环境执行；业务环境 UI 检查拦截全部非 GET 请求。没有调用真实模型或修改用户衣橱。
