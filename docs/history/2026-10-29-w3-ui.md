# 2026-10-29 · W3 界面与交互优化

用户要求修改 W3 的设计与交互。范围限补充计划、观察决定、实际处理及共用退出影响展示；不扩展 W4，不改后端契约或数据模型。保留原 W1/W2/W3 未提交改动。

## 调整

- 清单去掉大段宣传标题，双页签保留。数量缺口按需展开，可直接核对对应季节需求；已计划覆盖缺口时明确提醒，避免重复添置。
- 补充计划先展示进行中，已结束计划折叠；分页明确“已加载”口径。进度区分正式入库关联、取消及待完成，不把取消量算作入库。详情优先完成入库关联，需求来源与备注按需展开。
- 观察卡片把单品、当前依据和用户决定分开，避免说明挤在图片旁；图片失败保留占位。筛选项刷新后滚动到当前项；从决定页保存/返回保留原分组。
- 决定改为原生单选卡片，说明观察、保留、待处理及撤销的后果；离开保护保留。处理面板标题保持简短，选择按继续持有/退出分组；退出展示跨季需求数、低于目标项数及确认/待核对前后数量，仍需明确勾选和提交。
- 计划编辑按“补充什么”“用途与补充说明”分组，备注折叠，需求加载/空状态明确。关联与取消确认固定在面板底部，关闭返回触发按钮；成功后触发按钮消失时焦点回到计划标题。

## 设计依据

使用项目 ui-ux-pro-max，沿用暖白、深绿、Lucide 与 Base UI。`progressive disclosure forms --domain ux` 和缩小后的 `progressive disclosure --domain ux` 未命中需求，未套用返回的标题排版建议；采用技能优先表和项目既有表单分层规则。React 检索返回语义 HTML 与状态管理指南，采用原生 radio、details、button、link。检查 quick-reference §1–3 和 pro-rules，按 H5 实际范围验证；未引入新主题、字体、图片或动画依赖。
