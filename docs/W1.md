# W1 · 单品生命周期

需求：P-30；阶段顺序见 [衣橱整理计划](plans/wardrobe-organization.md)，实现验证见 [开发记录](history/2026-10-29-w1-lifecycle.md)。本页维护 W1 契约和实现边界。

## 入口与使用

“我的衣橱 → 单品详情 → 生命周期”，路由 `/wardrobe/:id/lifecycle`。保持四项主导航。页面按当前状态、日常管理、单品档案和时间线分组，归档入口在页尾。界面实现与验证见 [W1 界面优化](history/2026-10-29-w1-ui.md)。

- 补充获得资料：来源、获得日期、人民币金额、子类、位置、备注。全部可留空；0 元与未知不同。日期不得在未来，获得日期不能晚于退出日期。录入日期独立展示。
- 更新状况：未知/完好/轻微磨损/需要维修/严重损坏；合身/不合身/不适用/未知单独维护。不会自动切换可用性。
- 收纳与取出：只改变日常存放/换季收纳及位置，不自动清除待洗、维修原因。
- 修改可用状态：沿用 available/unavailable，可补充待洗/维修/其他原因；恢复可穿会清除不可用原因。
- 开始维修：显式标记需要维修、暂不可用及维修原因；完成维修必须重新确认状况和可用性，可继续保持待洗。
- 整理决定：未决定/继续保留/待处理及原因；待处理仍是持有，可撤回决定。
- 退出衣橱：单独确认发生日期与去向（转赠/出售/回收/丢弃/其他），不删除档案和图片；默认衣橱不再展示，在筛选“已退出档案/全部档案”可查看。
- 撤销退出：仅纠正误操作，关联当前最后一条退出事件、填写原因、重新确认可用性；复用原单品 ID。实际购入另一件同款仍需重新录入。
- 记录更正：追加关联原事件的日期/原因说明，不修改原事件，也不暗中重放旧状态。当前资料错误通过相应保存动作修正；误退出通过撤销退出修正。记录按保存版本倒序展示，补录日期不重新排列实际状态动作。
- 穿着天数从 WearRecord 与历史快照关联，按同单品同一天去重。无记录不表示从未穿过，不推断剩余寿命。

子类为稳定 UUID、归属大类和名称。W1 支持按现有品类新增、选择及清空子类；在获得资料编辑内创建后自动选中，保存资料才关联单品，取消子类草稿不清除已填资料；相同品类与名称复用，改大类前必须清除不兼容子类。预置子类、改名/停用及需求行影响处理已由 [W2](W2.md) 接续，不自动给旧衣服归类。

## HTTP 契约

沿用公共 `/api/v1`、Envelope、错误码、维护屏障。金额存储/响应为精确十进制字符串，最多 8 位整数及 2 位小数，不转二进制浮点；日期按北京时间判断未来。

| 接口 | 语义 |
|---|---|
| `GET /garments` | 新增 ownership=owned（默认）/retired/all；原筛选与分页保留，所有范围均排除 deleted_at |
| `GET /garments/{id}` | 原 GarmentView 加 ownership、subtype_id、lifecycle；已退出可读取，已删除仍 404 |
| `GET /garments/{id}/lifecycle` | 事件分页、穿着摘要及不受分页限制的 last_exit_event_id（供撤销）；limit 默认 30、1～100，cursor 为上一页末项 version，按 version 倒序；无记录天数 0、首末日期 null |
| `POST /garments/{id}/lifecycle` | 必须有 Idempotency-Key、expected_version、action、occurred_on；可带 changes、reason、related_event_id；返回新 GarmentView |
| `GET /garment-subtypes` | 当前子类列表 |
| `POST /garment-subtypes` | 必须有 Idempotency-Key，category 与 name；创建或返回同名子类 |

`action` 限定修改字段，完整 schema 见 [OpenAPI](../backend/openapi.json)：profile、condition、storage、availability、repair_start、repair_complete、decision、retire、restore、correct。不允许通过 profile 任意改 ownership/退出信息。退出现状只允许补资料、记录更正和撤销退出，不能重复退出或直接开始维修。

所有生命周期写入在同一事务中锁定单品、检查共享 version、追加事件及保存回执。同键同内容重发返回原结果；同键不同内容 409，旧版本 409，非法字段/跨品类子类/跨单品关联事件 422。不同操作键的并发旧版本仅一个成功。普通基础属性 PATCH 保留原协议；涉及 availability 时同步清理原因并追加事件，与新动作共用单品版本，其他属性修改不会伪造生命周期事件。

前端操作键与原负载在发送前保存本地；网络失败可重发，刷新不自动提交。版本冲突可保留输入、显式读取新版本后再次保存。未提交表单关闭/离开有确认。data_epoch 变化仍使用全应用草稿与缓存清理。保存动作使相关查询失效。

## 持久化和搭配约束

追加迁移 `0007_lifecycle`：

- garments 增加 lifecycle JSONB（精确金额字符串、可选资料及独立状态）、ownership（owned/retired）、subtype_id 外键。旧行 lifecycle={}、owned、subtype_id=null；不改 attributes、availability、version、created_at 或 deleted_at。
- garment_subtypes：稳定 ID、category/name 唯一。
- garment_events：单品、动作、发生日期、保存时间、共享版本、原因、关联事件、前后状态。单品/version 唯一，关联事件外键；应用仅追加记录，无编辑或删除事件 API。

统一可参与搭配条件为：未删除、非示例、持有中且 available。候选查询、锁定检查、历史复用后的失效提示、调整与最终提交均覆盖；最终提交持有单品行锁并检查当前状态/版本，退出先完成则拒绝结果。已锁定单品失效不静默解锁；历史快照和图片保持不变。已退出单品即使经旧接口改为 available 仍被排除。

初期未扩展照片识别和 Excel 模板；2026-10-30 用户授权补齐导入，当前阶段及字段以 [导入资料契约](IMPORT-DETAILS.md) 和 [实施计划](plans/import-organization.md) 为准。仍不增加必填项；模型候选白名单排除 lifecycle/ownership/subtype_id，避免发送金额、收纳位置、私人备注。W1 浏览、统计和保存不调用模型。

## 备份与兼容

新表注册到 Alembic 与备份表集合，原媒体引用保留。W1 历史备份版本为 app_version=`0.2.0-w1`、alembic_revision=`0007_lifecycle`；格式版本仍为 1。

沿用严格同版恢复规则：旧 `0006_recognition` 包不能直接覆盖 W1 数据库，会明确拒绝；需要使用匹配旧版应用恢复后，再执行正常迁移。升级前保留旧版完整包，升级后可生成 W1 包。新包完整恢复覆盖单品新资料、子类、关联事件、幂等回执及所有原业务内容，恢复后旧任务不自动执行。

W1 本身不做目标和缺口计算，该部分已由 [W2](W2.md) 接续；处理建议与全季退出影响已由 [W3](W3.md) 接入，整理会话已由 [W4](W4.md) 完成。

W3 补充约定：退出前必须读取全部季节影响；原 retire 写接口增加 impact_token 校验，旧幂等回执仍先返回。前端退出统一使用 W3 处理接口，保留决定同步当前已知整理原因。见 [W3](W3.md)。
