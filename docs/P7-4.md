# P7.4 · 衣橱利用情况

依据 PRODUCT P-26 与 [P7 计划](plans/P7-advanced.md)。本页维护行为和协议，实际交付进度见 [开发记录](DEVELOPMENT.md)。

## 使用与统计口径

- 从「我的衣橱 → 利用情况」进入 `/wardrobe/usage`。提供近 30 天、近 90 天和全部记录，默认近 30 天；范围、单品分组与页码保留在 URL，刷新和从详情返回保持。
- 按 Asia/Shanghai 自然日计算，包含今天：30 天为今天往前 29 天，90 天为往前 89 天；不计未来记录。全部记录的起始日为当前衣服最早的已记录穿着日期，无记录时为 null。
- 分母为当前持有、未软删除、非示例衣服；暂不可穿也属于当前衣橱。已退出和已删除衣服仍保有历史快照，但不参与当前库存统计。
- 只读取实际 `wear_records` 与不可变 `outfit_revisions`，同时涵盖手动与 AI 来源；同一真实单品同一天去重，重复快照项也去重，未拥有建议不计入。未记录穿着的生成/收藏不算穿过。
- 有记录占比为期间穿着天数大于零的单品数 / 当前衣服总数。零分母返回 null，界面显示「—」，不展示虚假的 0%。汇总来自完整范围，不累计第一页冒充总量。
- 常穿列表仅含期间有记录单品，按记录穿着天数降序、最近记录日期降序、UUID 升序排序。无记录列表按入库时间降序、UUID 升序排序。每件显示期间记录天数、最近一次记录日期、入库日期与当前可用状态。
- 「最近记录」可以早于所选窗口；「期间无记录」不等于从未穿过或真实闲置，新入库也不表示闲置了整个窗口。入库日期为正式入库时间，非购买/获得日期。
- 总数与本页在同一数据库快照读取。翻页之间是实时重新统计，其他页面修改记录后可能改变排序；空页提供回到第一页。页面重新进入、刷新及应用内修改后的查询失效会读取最新数据。

## 界面与交互

- 数量卡片直接切换常穿/期间无记录分组，选中同时显示边框和勾选；统计口径按需展开，保留“无记录不等于没穿过”的提示。
- 加载与失败时保留时间/分组控件和焦点，新范围返回前不展示上一范围数字；结果区播报当前总量与条目范围。翻页将焦点移到列表标题，刷新与返回继续沿用 URL。
- 单品单列展示，区分可用状态与历史记录；长名称完整换行，缺图提供占位。指定单品显示图片和具体阻塞原因，生成按钮旁提供查看状态入口，移除保留条件草稿。

## 围绕单品搭配

- 可穿单品的「围绕这件搭配」进入条件页，只携带明确的单品 ID 并读取当前状态；不写数据库、不调用模型。条件页保留已有条件草稿，显示指定单品，可显式移除。
- 暂不可穿单品先提供查看状态入口；页面间状态改变、删除、退出或示例会阻止新生成，不静默解除指定。条件页每 10 秒只读复核，提交时后端再次强制检查。
- 点击「生成搭配」才以 `anchor_garment_id` 创建独立会话并将其放入现有锁定集合，再通过既有生成接口提交。旧会话与历史保留；新会话不人为制造一份“实际穿着”或占位搭配快照。
- 首次生成前允许显式清除原锁定，不允许在没有选中方案时随意追加其他衣服。生成前和 worker 读取上下文时再次检查有效性，最终方案必须包含锁定单品。生成后的锁定、替换与选择遵守原规则。
- 创建或生成响应不明时保存原负载及幂等键，刷新不重发；用户明确重试才继续。未提供 anchor 的旧会话创建请求保持升级前的幂等摘要，旧回执仍可重放。

## 接口与边界

`GET /wardrobe/usage?range=30|90|all&view=worn|unrecorded&offset=0&limit=20`

- offset：0～1,000,000；limit：1～100。后端负责完整过滤、排序和分页。
- `UsageReport`：range、view、as_of、window_start、timezone、total_garments、recorded_garments、unrecorded_garments、recorded_ratio、items、total_items、offset、limit、next_offset。
- `UsageItem`：garment_id、name、category、image_url、availability、created_at、wear_days、last_worn_on。日期和图片均来自真实记录，不补造未知名称、图片或穿着。
- `POST /outfit-sessions` 增加可空 `anchor_garment_id`，不可与 `base_revision_id` 同时提供；不可用/删除/退出/示例目标返回 409。现有版本及幂等规则保持。

`services/wear_stats.py` 与 W1 生命周期摘要共用按单品/日期聚合；P7.2 保持相同去重口径，其组合统计仍由原服务负责。查询使用两条 SQL（总量与页数据），不逐件查询；所有数据来自现有表，无新增迁移或持久统计副本。备份格式和 schema head 仍为 `0.7.3-feedback` / `0012_wear_feedback`，无需覆盖已有数据。

## 验证

固定数据验证窗口边界、同日/重复项去重、两种来源、记录修改/删除、当前库存资格、零分母、跨页及入库日期；500 件容量测试记录 SQL 数量和延迟。新增锁定测试包含不可用目标、生成保留、旧回执兼容和失败恢复。浏览、筛选、刷新零模型调用，生成仅在隔离 Fake 环境验证。
