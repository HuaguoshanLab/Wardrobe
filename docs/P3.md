# P3 · 天气与偏好交付

日期：2026-10-26。实现偏好、默认城市、天气适配/缓存、定位失败降级和首页条件草稿。真实和风账号已完成城市/实况/预报小样本验收，见[验收记录](history/2026-10-27-qweather.md)。手机使用获用户通过反馈，具体定位场景未单独记录。

## 页面与数据

- 设置页：风格、版型、冷热倾向、喜欢/避开的颜色、补充说明。空值表示未知；用户显式保存，不从行为推断偏好。
- 默认城市：按名称或经纬度查询和风 GeoAPI，展示省/市/区县供选择。定位仅由按钮触发，失败立即提示搜索/手填，不重复请求授权。手机局域网 HTTP 无需先配 HTTPS。
- 未配置或不可用时，可以选择大陆省级地区并手填城市，标记 `source=manual`、位置未核验，没有伪造 Location ID 或坐标。手填城市用于标识手动天气；自动天气须从和风搜索结果选择。
- 首页：展示当前实况与今日预报，分别标注时间、日期、来源及过期状态。条件含场合、风格、季节、自定义标签、文字补充及手动天气覆盖。0℃合法；温度和天气现象必须同时提供。
- 条件由“保存并核对条件”提交校验，不生成搭配。草稿按北京时间日期＋城市保存在当前浏览器；换城市/跨日使用不同草稿。跨设备会话、聊天、生成、结果快照属于 P4，未实现。
- 旧条件草稿中的已删除标签会明确提示，支持点击移除；保留其他标签、文字和手动天气。提交失败后重新查询标签，覆盖页面打开后标签被删除的情况。
- `style_codes=null` 表示继承最新长期偏好；显式数组（包括空数组）覆盖风格。长期偏好说明与本次说明分别保留，P4 需按本次要求优先使用。

新增迁移 `0003_weather_profile` 接在 P2 迁移之后：`profiles`、`weather_cities`、`weather_cache`。现有 owner/data_epoch/示例标记仍由 system_state 持有，不复制权威状态。

偏好与位置分别计版本，避免无关编辑冲突。PATCH 需要 expected_version 与 Idempotency-Key，回执先于版本检查；偏好内未出现的字段保持不变，显式 null/空数组清空。用户草稿不会被后台 refetch 覆盖；冲突需重新载入后编辑。偏好保存失败后，刷新或重新进入设置会恢复持久化的待确认请求；用户点击“重发原保存操作”才按原始请求内容、expected_version 和幂等键重发，不自动写入。待确认期间暂禁编辑，用户也可明确放弃草稿并重新载入；成功载入后才清除待确认记录。API 不接收未在城市目录核验的和风城市对象。

## 天气适配与时效

- 使用账号专属 HTTPS Host；GeoAPI `/geo/v2/city/lookup` 的坐标为经度,纬度，`range=cn` 后还过滤国家和大陆省级行政区；天气 v1 路径为纬度/经度。
- 当前实况 `/weather/v1/current/{lat}/{lon}` 缓存 15 分钟；当日预报 `/weather/v1/daily/{lat}/{lon}` 缓存 60 分钟。按城市 ID、坐标、种类、北京时间日期隔离，并保存在 PostgreSQL。
- v1 当前响应未提供观测时间，`observed_at=null`；界面明确获取时间不等于观测时间。日预报只选择白天起始时间属于北京时间今天的条目，不将实时数据冒充未来预报。
- 摄氏温度与毫米降水校验单位；缺少必需字段或错误单位返回无效响应。体感、降水等可选字段未知仍为空。
- 每个上游请求超时 5 秒，最多两次尝试，仅传输错误/5xx 重试一次；401/429 不重试。实况与预报独立失败。全无数据返回 503；部分数据或过期参考可返回 200，但 errors/stale 必须显示。
- 过期缓存不能默认为可用天气，只供参考并提示手填；无可用实况时 P4 生成必须要求手动输入，不能靠预报字段或模型猜测温度。
- 首页只读轮询每分钟，后端仍按 TTL 复用；天气查询、偏好查询、刷新均不创建模型 Job。
- 归因文字来自上游，按纯文本展示；附和风官网链接。不执行返回内容，不将其作为系统提示。

## 配置与验证入口

配置仅在后端。根 `.env.example` 提供：

```text
QWEATHER_HOST=账号专属子域.qweatherapi.com
QWEATHER_API_KEY=控制台的 API Key
QWEATHER_TOKEN=
```

Host支持账号单层或账号＋分区双层子域，严格限制在 qweatherapi.com 下，不接受协议、路径、端口或其他域名。按控制台原值填写。

只选一种认证；TOKEN 非空时优先使用 Bearer JWT，使用前由用户生成并在过期前更新，本轮没有私钥签发/自动续期。API Key 仅经 `X-QW-Api-Key` 标头发送，凭据不放 URL、OpenAPI 响应或浏览器存储。`.env` 不提交。修改后运行根 README 的 Compose 构建启动命令。

未配置时 capability.weather=unconfigured；凭据和 Host 齐全时为 configured，仅代表有配置，不证明请求成功。实际可用性看天气请求结果。天气不受模型的 PROVIDER_MODE=fake 影响，没有自动 Fake 天气。官方计划自 2027-01-01 限制 API Key 日请求量，届时按账户条件使用 JWT。

检查命令与真实结果见 [P3 开发记录](history/2026-10-26-p3.md) 及 [复核修复记录](history/2026-10-26-p3-review-fixes.md)。测试没有使用真实凭据，HTTPX/RESPX 覆盖官方响应字段、单位、坐标顺序、行政区过滤、401/429/5xx、缓存过期和城市隔离；PostgreSQL 覆盖偏好并发/幂等/清空及条件优先级。
