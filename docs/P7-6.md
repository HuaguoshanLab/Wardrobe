# P7.6 · 按收纳位置找衣服

范围依据 PRODUCT P-36 与 [P7 计划](plans/P7-advanced.md)。本阶段复用 W1 的可选位置文本，不增加地点层级、位置实体、二维码或独立库存。实施验证及部署状态见 [开发记录](DEVELOPMENT.md)。

## 衣橱入口与范围

- 「我的衣橱 → 位置」打开已有位置清单；可搜索、加载更多、查看“未填写位置”，选择后回到衣橱明细。位置保存在 URL，刷新和进入单品再返回保留筛选。
- 位置数量与明细共用名称、品类、季节、场合、可用性、标签及档案范围。默认只统计当前持有、非示例、未删除单品；待洗、维修、换季收纳仍按实际位置计数。显式选择已退出/全部档案时，位置统计随档案范围变化。
- 普通衣橱保持原示例展示。启用任意位置范围（包括“全部位置”）时明细排除示例，和位置数量一致；界面明确“不含示例”。移除位置筛选同时移除模式和名称，恢复原衣橱策略。
- 未填写、空字符串和纯空白归“未填写位置”；已填文本去首尾空白后按完整文本聚合和精确筛选。保留大小写、内部空白、标点和不同写法；不猜测同义、不修改旧文本或历史事件。
- 长名称在清单完整换行；衣橱紧凑筛选条省略显示，位置面板的“当前选择”可展开查看全文，移除按钮保留完整可访问名称。

## 位置复用与保存

- W1 的「补充获得资料」「收纳位置」及 P7.5 的「修改收纳位置」增加“选择已有位置”。复用清单默认读取当前持有的真实单品，不受另一个页面的筛选限制。
- 可以搜索、清空搜索、翻页、选择，也可直接输入新位置。分页失败保留已加载条目并重试缺失页，等待搜索结果时禁用旧条目。选择只填草稿并返回输入焦点，不自动保存、移动其他单品或创建实体；读取失败可重试，保留手工输入；“返回手动填写”关闭建议并将焦点交回输入框，选择后提示保存才生效。
- W1 明确提交 `location` 文本时去首尾空白、纯空白写为 null；没有提交 location 的动作不整理旧位置。P7.5 沿用原 trim 语义，清空仍须选择独立动作。
- 位置变更沿用 W1 的版本、操作键及不可变事件；批量修改沿用 P7.5 的逐项结果和原请求恢复。只改位置不改变是否可穿、待洗/维修原因、换季收纳或其他档案。
- 单件、批量保存后使衣橱列表和位置查询缓存失效。搜索、浏览、选位置均零模型调用。

## 查询契约

### `GET /wardrobe/locations`

- `q`（名称，最多 100 字）、`category`、`season`、`occasion`、`availability`、`tag_id`、`ownership=owned|retired|all`：与衣橱明细相同；不以位置筛选限制统计范围，不把已选位置过滤成只剩自己。
- `location_q`：最多 120 字，去首尾空白后做包含搜索；`%`、`_` 和反斜线按普通字符处理。搜索不合并大小写不同的位置，只用于匹配名称。
- `limit`：默认 20，1～100；`cursor`：上页最后一个规范化位置名称，最多 120 字。使用 PostgreSQL C 排序及同口径 keyset 分页；位置可以含中文、标点和 URL 保留字符。
- 返回 `LocationList`：`items[{location,count}]`、`next_cursor`、`total_garments`、`unassigned_count`、`matching_locations`。count 来自完整匹配库存，不由前端累加已加载衣服。
- `total_garments` 和 `unassigned_count` 反映衣橱筛选范围，不受 location_q 或游标影响；`matching_locations` 反映名称搜索匹配的已填位置总数，不包含未填写桶。
- 三条固定 SQL 在同一 REPEATABLE READ 快照内计算总量、匹配位置数和一页位置；并发修改不会让同一响应里的总量与明细混用前后状态。不同请求间库存可变化，不承诺跨请求冻结；修改后重新查询。

### `GET /garments` 增加位置筛选

| 参数 | 语义 |
|---|---|
| 不传 `location_mode` | 原衣橱语义，不能单独传 location |
| `location_mode=all` | 全部真实单品位置（含未填写），排除示例 |
| `location_mode=unassigned` | 未填写位置，排除示例 |
| `location_mode=named&location=…` | 按去首尾空白后的名称精确匹配，排除示例 |

named 必须携带非空名称，最多 120 字；其他模式不得携带 location。非法组合明确 422，不静默放宽成全衣橱。其他条件、衣服排序和 UUID 游标分页保持。

## 数据与兼容

- 新接口只读，复用既有 `lifecycle.location` JSON 字段，无新表、无新增迁移、无旧数据回填。
- 旧 `/garments` 请求保持兼容；公开 schema、OpenAPI 和生成 TypeScript 同步。
- 维护屏障覆盖新查询。恢复后的 data_epoch 沿用公共清理机制，清空 Query 缓存及旧草稿；URL 的位置仅是重新查询条件，不执行写入。
- 备份格式/schema 仍为 `0.7.3-feedback` / `0012_wear_feedback`；位置和生命周期事件已经在原备份范围内。
