# 产品需求与验收基线

版本：0.2。更新日期：2026-10-26。P-01 至 P-23 记录已确认产品行为；细则和验收包含为落实需求补充的工程默认，见 [DECISIONS](DECISIONS.md)。审查及覆盖关系见 [REVIEW](REVIEW.md)。实现状态见 [DEVELOPMENT](DEVELOPMENT.md)，P2 工程闭环和外部验收边界见 [P2](P2.md)。

## 1. 目标与范围

为个人整理真实衣橱，并根据天气、场合和偏好获得可调整、可保存的穿搭。第一版供用户自己在电脑本地 Docker 运行，手机同一 Wi-Fi 访问。

支持安卓 Chrome、iPhone iOS 18 Safari；第一版不适配微信。后续可用 Capacitor 套壳，但首版不开发原生 App、账号注册、多用户权限、商城、虚拟试穿、自动长期偏好学习或向量检索。

本产品包含智能编排，但“使用 Agent”不允许绕过用户确认或数据库业务规则。

## 2. 已确认功能

| ID | 功能 | 必须遵守的行为 |
|---|---|---|
| P-01 | 初次体验 | 提供一个可删除的示例单品，不以多件演示衣服替代用户衣橱 |
| P-02 | 衣橱范围 | 衣服、鞋、包和帽子、围巾、腰带、首饰等配饰；配饰非每套必选 |
| P-03 | 基础属性 | 图片和品类必填；颜色、季节、场合等允许未知并可后补；已保存数据可编辑 |
| P-04 | 分类与标签 | 基础词表统一，支持自定义标签，标签可用于筛选和搭配条件 |
| P-05 | 可用状态 | 默认“可穿”，可改“暂不可用”并手动恢复；AI 必须排除不可用单品 |
| P-06 | Excel 导入 | 用本项目固定 `.xlsx` 模板，图片与标签同文件、每行一件；预览修改后确认；不再做 CSV 导入 |
| P-07 | 照片录入 | 批量照片 → AI 预填 → 表格逐件审核 → 确认入库；每张照片对应一件 |
| P-08 | 图像范围 | JPEG、PNG、WebP、HEIC/HEIF；保留原件并自动转换。单品平铺/挂拍，鞋可一双一起拍 |
| P-09 | 去背景 | 自动生成去背景图，保留原图，效果不好时可切回；不重画款式、颜色和图案 |
| P-10 | 天气与位置 | 和风天气；仅中国大陆；能定位就定位，失败或不可用时手动选城市并记住；HTTPS 后续配置 |
| P-11 | 天气降级 | 服务失败可手动填写温度和天气，不阻止搭配；支持更换城市及手动覆盖 |
| P-12 | 需求入口 | 快捷选项＋聊天补充；生成后按钮或聊天都可继续调整 |
| P-13 | 长期偏好 | 保存明确填写的风格、版型、怕冷/怕热、颜色喜好等；可编辑；本次明确要求优先 |
| P-14 | 生成数量 | 一次最多三套有实际差异的搭配；衣服不足不强凑 |
| P-15 | 结果展示 | 单品图片组合卡片＋理由，无模特上身效果图 |
| P-16 | 锁定与调整 | 可锁定一件或多件，替换指定单品或重搭未锁定部分；按钮与聊天遵守相同条件 |
| P-17 | 冲突与缺项 | 保留锁定，给可行部分并说明未满足条件；可给衣橱外建议，明确“未拥有”，无购物链接 |
| P-18 | 历史与收藏 | 自动保存生成与调整结果，支持历史删除、手动收藏、命名和取消收藏 |
| P-19 | 穿搭日历 | 通过显式“记录穿着”记为今天或补记日期；支持修改删除；生成和收藏不等于穿过 |
| P-20 | 历史快照 | 保留当时图片和属性；衣服修改/删除不破坏历史；复用时检查当前可用性 |
| P-21 | 首页与视觉 | 首页“今日穿搭”，衣橱独立入口；管理页紧凑实用，搭配/收藏页注重视觉 |
| P-22 | 生成时机 | 点击生成才调用 AI；刷新、重新打开、天气更新和恢复连接不重复生成 |
| P-23 | 备份恢复 | 手动导出和恢复图片、属性、偏好、收藏、历史和穿搭记录；排除 API 凭据；覆盖前确认 |

## 3. 页面结构

以下 URL 是工程设计，导航名称可微调，但不能遗漏能力。

| 页面 | 建议路由 | 主要内容 |
|---|---|---|
| 今日穿搭 | `/` | 城市天气、快捷条件、聊天补充、显式生成、恢复已有任务/结果 |
| 衣橱 | `/wardrobe` | 网格、分类筛选、搜索、可用状态、上传与 Excel 导入入口 |
| 单品 | `/wardrobe/:id` | 原图/去背景选择、属性编辑、状态修改、删除 |
| 导入审核 | `/imports/:id` | 每行一图、可编辑标签、校验错误、识别状态、确认 |
| 搭配会话 | `/outfits/:sessionId` | 最多三套、选择、锁定、替换、聊天、未满足条件 |
| 历史/收藏 | `/collections` | 历史和收藏切换、固定版本详情、复用、删除 |
| 穿搭日历 | `/calendar` | 实际穿着记录、补记、编辑、删除 |
| 设置 | `/settings` | 长期偏好、默认城市、备份恢复、服务配置状态 |

生成的结果不是聊天纯文本：图片卡片与可操作单品来自结构化数据。用户应能从失败状态恢复到相应表单或任务，而不是只能刷新重来。

## 4. 关键行为细则

### 导入

- Excel 已有属性直接读取；没有填写的可选字段保留未知，不为了填满表格而自动编造。
- 两个入口共用审核与确认语义，上传/识别成功不代表已经加入衣橱。
- 只确认通过图片及品类校验的行；错误明确定位到行和字段，允许修正、移除或重试。
- 识别/去背景失败不阻塞其他行。若转换后无法得到可查看的图，说明失败，不能把损坏图片当有效图片入库。
- 手机审核保留表格逐行语义，图片、品类、状态优先显示，其余属性展开编辑。
- 人工修改或主动清空的字段不被晚到的 AI 结果覆盖；确认入库后不再自动修改属性。两种入口都处理转换和去背景；未配置识别服务时允许手工完成审核，并明确提示配置状态。

### 搭配

- 搭配结构随服装调整：连衣裙可替代上下装，外套按需求加入，配饰可省略。
- “未拥有”建议是文字/类型建议，不伪造衣橱 ID 或已拥有照片。不能用几套全是外部建议的方案凑三套。
- 可用性和锁定是后端硬约束。若锁定单品后来不可用或删除，保留旧结果、明确冲突，要求用户解锁/恢复/替换，不能静默违反。
- 季节、场合、风格是匹配依据，用户明确要求可改变偏好；缺少厚度/保暖性数据时必须承认不确定性。
- 自动保存每次成功生成/调整的完整版本；不把每个流式文本片段当历史版本。
- 历史复用不直接恢复已删除的衣服，也不修改当时快照。
- “只替换某件”保持所有非目标单品，包括未锁定的单品；“重搭未锁定部分”才扩大调整范围。聊天指代不明确时先澄清，不自行改动。
- 选中方案、锁定和已提交条件保存在会话；刷新或另一台手机打开可恢复。首次没有会话不自动生成；真实衣橱为空时提示上传，不调用模型凑结果。
- 删除历史入口不取消收藏、不删除穿着记录及其快照；如果删除当前选中结果，则清空该选择并提示，不自动生成替代。

### 天气

- 浏览器能提供坐标不保证天气服务成功；两种失败分别提示。
- 无可信 HTTPS 的手机局域网访问可直接使用手动城市，不能强制用户配置证书才进入应用。
- 天气需标注来源、日期/时间与手动输入状态。不能把当前天气充当未来日期预报。
- 日历首版记录实际穿着，不把未来穿搭计划默认为用户已经确认的功能。

## 5. 验收场景

| ID | 场景 | 可观察结果 |
|---|---|---|
| A-01 | 首次进入后删除示例，再刷新 | 示例不复活；显示真实空衣橱状态 |
| A-02 | 照片仅确定品类，其他留空 | 可确认入库；状态可穿；未知属性保持未知 |
| A-03 | 同批三张照片中一张识别失败 | 两张可继续确认；失败行可人工填写或重试 |
| A-04 | Excel 图片锚点与文件内部顺序不同 | 按行匹配正确；无法确定时报错，不猜图片 |
| A-05 | Excel 已有季节标签 | 导入后保留，默认不调用识别覆盖 |
| A-06 | 上传 HEIC 并切换原图/去背景 | 原件留存；两种视图可用或明确显示某衍生步骤失败 |
| A-07 | 衣服标为暂不可用后生成 | 后端结果不包含该衣服 |
| A-08 | 锁外套，通过按钮和聊天分别换裤子 | 外套在两次新结果中都保持不变 |
| A-09 | 锁定后在另一页面将衣服设不可用 | 新调整返回可解释冲突，不继续使用不可用衣服 |
| A-10 | 模型返回不存在的单品 ID | 后端拒绝/有限修正，不显示成真实衣橱单品 |
| A-11 | 衣橱不足以构造三套 | 返回较少方案或可行部分，明确未拥有建议及缺项 |
| A-12 | 生成中刷新、关闭页面后重新打开 | 恢复同一任务/结果，不再次发起模型生成 |
| A-13 | SSE 重复、断开后恢复 | 事件去重，显示一致；不重复创建历史或扣费请求 |
| A-14 | 已保存历史后修改/删除原衣服 | 旧图片和属性仍可查看；复用提示当前失效单品 |
| A-15 | 收藏某套，但未点记录穿着 | 收藏可见，日历无自动记录 |
| A-16 | 补记昨天实际穿着并修改/删除 | 日历对应日期正确更新，不改历史搭配版本 |
| A-17 | 手机 HTTP 无法定位 | 能手动选城市并继续；天气失败可手动输入 |
| A-18 | 备份后清空测试环境并恢复 | 图片及业务记录一致恢复；不泄露凭据，旧任务不会自动执行 |
| A-19 | 多次点击确认导入/生成 | 同一操作不重复创建衣服或生成任务 |
| A-20 | 没有 API 配置但启用 Fake Provider | 明确展示模拟来源；不声称已连通真实服务 |
| A-21 | 任务运行中 worker 崩溃 | 状态可检测为中断；结果不明的外部调用不盲目重发 |
| A-22 | 锁定与用户场合要求冲突 | 保留锁定，显示未满足要求，不谎称完全符合 |
| A-23 | 只换裤子，其他单品均未锁定 | 所有非目标项保持；只有明确重搭才可改变其他未锁定项 |
| A-24 | 识别中手改颜色、清空季节，再确认 | 晚到识别不覆盖人工值或清空值，不修改已确认衣服 |
| A-25 | 已选方案并锁定，刷新或换手机打开 | 恢复会话、选中项、锁定、已提交条件及任务；不自动生成 |
| A-26 | 同批确认包含有效行、错误行和版本冲突行 | 按行返回结果；有效行入库，重发不重复创建，修正后可单独确认 |
| A-27 | 分别观察导入、搭配、备份任务并恢复 SSE | 返回各自结果类型；终态停止重连；过期事件用查询恢复 |
| A-28 | 业务结果已提交但检查点未保存时崩溃，或队列重复投递 | 读已提交结果，不再创建版本或发起同一步模型调用 |
| A-29 | 取消与结果提交并发 | 只有一个确定终态；确认终态前不能另起会话任务 |
| A-30 | 备份时 worker 写入，恢复中重启或文件缺失 | 不发布不一致备份；恢复状态可查询，失败可回退且不返回假成功 |
| A-31 | 模型未配置，或持续返回非法结果 | 无配置时可手工录入；模型运行有总预算，耗尽后明确失败 |
| A-32 | 手填 0℃、更换城市、缓存过期且天气失败 | 0℃有效，城市天气不串用，失败提供手工输入且不伪造天气 |
| A-33 | 修改标签和长期偏好，再设置本次覆盖条件 | 筛选和下次输入使用最新值；本次明确要求优先；旧快照不变 |
| A-34 | 从历史删除已收藏或已记穿着的搭配 | 对应收藏和日历仍能看原图与属性；首页不自动重新选中 |

## 6. 不属于本轮范围
