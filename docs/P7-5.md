# P7.5 · 日常洗衣与批量管理

范围来自 PRODUCT P-35 与 [P7 计划](plans/P7-advanced.md)。实际实现与验证记录见 [交付记录](history/2026-10-30-p7-5.md)，后续界面优化见 [UI/UX 记录](history/2026-10-30-p7-5-ui.md)。

## 操作与界面

- 从「我的衣橱 → 洗衣与批量管理」进入 `/wardrobe/care`。待洗、可穿、全部单品均只显示当前持有、未删除、非示例衣服；待洗必须同时为 unavailable 且 unavailable_reason=washing。
- 按名称、品类筛选，分组和筛选保存在 URL；每次加载 20 件。逐件勾选、最多 20 件，分页/筛选不增加或清除已选；可只看已选并移除。不提供全部筛选结果自动全选。
- 操作设置在清单前；长清单的核对栏保持可见，显示已选数量和当前动作。“更改操作”返回设置并聚焦操作控件；矮屏取消吸顶以保留浏览空间。没有草稿时，从可穿分组进入默认“标为待洗”；已有草稿优先保留。
- 已选快照、动作和输入保存在本浏览器；提交前重新读取所选单品，在确认面板展示缩略图、最新状态、目标变化、当前可识别的状态冲突和版本变化，再明确确认。预览不代替后端校验；读取失败时显示失效单品名称并阻止提交，允许重读或返回选择列表移除失效对象。
- 标为待洗：可穿改为 unavailable/washing；已经待洗返回无需修改；维修/其他不可穿原因保持并返回冲突。
- 洗好了：仅 unavailable/washing 恢复 available 并清除该原因。其他状态返回冲突，不静默完成维修，也不因记录穿着或经过时间自动变更。
- 添加/移除标签只增减指定集合，不覆盖其他标签；需要 1～30 个有效标签，添加后仍不超过单品原有 30 个标签上限。删除的标签明确拒绝，不自动创建。
- 修改位置须填写 1～120 字的非空位置；清空是单独动作。只变更 location，保持可用性、日常/换季收纳及其他档案字段。
- 结果显示成功/失败数量，失败项和原因优先展开，成功明细可按需展开；提交后焦点落在结果摘要。成功项从选择中移除。重新处理只选未成功项，恢复原操作参数，再读取当前状态并重新确认；不自动更新旧请求的版本或负载。

## 接口与事务

`GET /wardrobe/care?group=washing|available|all&q=&category=&cursor=&limit=20`

复用 `GarmentList` 和衣橱稳定游标，limit 1～100，名称查询最多 100 字；只读，不调用模型。

`POST /wardrobe/care/actions` 必须携带 `Idempotency-Key`，JSON 为 `CareBatch`：

- items：1～20 项，单品 ID 与单项操作 ID 均不得重复。
- 每项 id（UUID）、garment_id、expected_version、action；action 为 mark_washing / wash_done / tags_add / tags_remove / location_set / location_clear。
- tag_ids 仅供标签动作，location 仅供 location_set；不接受与动作无关的非空参数，防止用户输入被静默忽略。清空位置不通过空字符串表达。
- 返回 `CareResult.items`：id、garment_id、success、changed、code、message、garment（成功时的操作结果快照）。无需变化也成功，但不增加版本或事件。失败保留错误原因，成功回执不冒充此后实时状态。

服务在一个事务中使用统一衣橱锁与逐项 SAVEPOINT；每件校验当前所有权、删除/示例状态和共享版本。洗衣/位置复用 W1 `apply_in`，标签复用基础属性校验；标签删除先获得同一衣橱锁，避免批量操作校验和删除竞争。普通基础编辑仍保持原协议。

整批及单项回执复用 `operation_receipts`，命名空间为 wardrobe-care / wardrobe-care-item；无需新表或迁移。相同键和相同内容返回原结果，包括原失败项；相同键不同内容返回 409。不同批次键复用单项 ID 也只回读原回执。新一轮重试必须明确生成新的单项 ID，且只包含未成功项。

## 恢复与数据保护

- 浏览器发请求前保存原键、原负载及对象名称；断网/响应不明时刷新不自动重发，用户明确重发才回读原回执。完整响应通过 schema 校验并保存结果后才清理待发请求；整批明确拒绝才允许返回编辑。
- 维护屏障覆盖读写，恢复后的 data_epoch 变化沿用 Shell 清空所有 `wardrobe.*` 草稿、待发操作、结果和 Query 缓存。
- 回执、生命周期事件、单品属性均属于现有备份表。备份格式/schema 继续为 `0.7.3-feedback` / `0012_wear_feedback`，本次不改变兼容结构。
- 无新增媒体或模型任务；旧事件、历史快照及图片保持。故障/恢复只在独立环境验证，不在业务库制造样例或覆盖数据。
