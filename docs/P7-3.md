# P7.3 · 穿后反馈

范围依据：PRODUCT P-25 和 [P7 计划](plans/P7-advanced.md)。本页维护行为与字段，实际进度见 [开发记录](DEVELOPMENT.md)。

## 用户行为

- 日历中的实际穿着记录提供「穿后反馈」，手动与 AI 来源一致。未记录穿着的搭配没有此入口。
- 一条穿着记录保存一份反馈，反馈对象为整套或该不可变快照中的一件真实单品。更换对象是修改同一份反馈；不新增第二份实际穿着记录。
- 冷热感受：未评价/偏热/偏冷/冷热合适；舒适度：未评价/舒适/一般/不舒适；配色满意度：未评价/满意/一般/不满意；备注最多 500 字。至少选择一种感受或填写非空备注。
- 感受不写入衣服属性、不改历史 revision、不改变长期偏好或自动推荐。原单品后续删除或退出，仍能反馈当时快照中的真实单品；不能选择其他记录里的单品或未拥有建议。
- 未保存内容留在本浏览器；保存结果不确定时保留原请求与幂等键，刷新不重发。冲突时可保留输入、读取最新版本再核对保存。
- 「用于下次搭配」展示可编辑参考文字，带到条件页核对后加入已有补充，不清除原条件。总长度超过 1000 字时要求精简，不截断；只有显式生成才使用。
- 「保存为长期偏好」展示已有补充和拟保存的完整补充，可编辑后确认。仅写入偏好 notes，不从一次偏热推断全局怕热，也不推断颜色或版型。确认前不写偏好，保存失败不丢反馈；重试原键与原负载。
- 删除反馈不撤销另行保存的偏好，提供偏好管理入口；删除实际穿着记录时级联删除附属反馈，保留独立偏好、收藏和搭配快照。修改记录日期保留反馈关联，未来使用文字按该记录最新日期生成。

## 界面与编辑

感受以三列选项展示，各组「清除」恢复未评价。保存状态集中展示；桌面并排显示填写与用途，手机依次显示。两个用途预览各自保留本次页面内编辑，切换不重置；反馈修改后需先保存才能继续新的提交。已展开预览的文字不被新反馈静默覆盖，页面提示核对。条件页清空参考文字仍可重写，刷新保留空草稿，明确「暂不使用」才关闭。实现与验证见 [界面优化记录](history/2026-10-30-p7-3-ui.md)。

## 数据与接口

`wear_feedback` 以 `wear_record_id` 为主键及级联删除外键，包含可空 JSONB `feedback`、单调递增 `version`、`updated_at`。无记录时版本 0；删除反馈保存空内容和递增版本，避免旧编辑页在删除后以版本 0 复活内容。穿着记录与反馈使用同一父记录行锁，与删除/改日串行化。

| 接口 | 含义 |
|---|---|
| `GET /wear-records/{id}` | 固定实际记录及不可变搭配快照 |
| `GET /wear-records/{id}/feedback` | 反馈内容、版本及更新时间；无反馈返回 null，不创建反馈行 |
| `PATCH /wear-records/{id}/feedback` | `expected_version >= 0` + `feedback`；创建/修改使用 `Idempotency-Key` |
| `DELETE /wear-records/{id}/feedback` | `If-Match >= 1` + `Idempotency-Key`；清除内容并保留版本 |

反馈字段：`garment_id: UUID|null`（null 为整套）、`thermal: hot|cold|just_right|null`、`comfort: comfortable|neutral|uncomfortable|null`、`color: satisfied|neutral|unsatisfied|null`、`notes: string`。版本冲突 409，跨快照目标 422，父穿着记录不存在 404；同键不同负载 409。请求回执与反馈在同一事务提交。

偏好复用 `PATCH /profile/preferences` 的版本、幂等与局部合并语义，只显式提交 notes；其他字段保留。反馈本身不进入生成上下文，只有已确认的偏好或条件文字通过现有生成提交冻结。后续反馈/偏好修改不重写旧上下文，本次明确需求仍优先。

## 升级、备份与验证边界

迁移 `0012_wear_feedback` 仅增加表，已有业务行不重写。模型注册表纳入反馈，完整备份包含其内容、版本和回执。备份精确版本更新为 `0.7.3-feedback` / `0012_wear_feedback`；旧版本备份不得在新版本直接恢复，应使用匹配的旧应用/迁移环境。健康检查同步新迁移版本。有反馈行时拒绝降级删除表，应使用升级前恢复点。

反馈是确定性记录与可编辑文字，不需要真实模型验收。Fake 流程验证已确认偏好/条件被下一次提交读取；这不等于真实模型审美或真机验收。运行证据见 [本阶段记录](history/2026-10-30-p7-3.md)。
