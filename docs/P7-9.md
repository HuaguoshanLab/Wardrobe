# P7.9 · 参考图搭配

需求 P-28；工程默认与数据协议在本文维护，验收证据见 [交付记录](history/2026-11-12-p7-9.md)。

## 用户行为

入口为「穿搭记录 → 参考图搭配」，不增加主导航。一次上传一张参考图，上传只保存原件和标准衍生图，不创建衣服、不调用模型。支持 JPEG/PNG/WebP/HEIC，20 MiB、64 MP、单帧；按原有媒体流程处理方向和剥离元数据。

用户明确点击分析并确认发送后才发送不超过1280边长的 JPEG 衍生图。品类、颜色、风格、内外层次均为可编辑线索；未选值保持未知。多人/主体不明确时后端清空全部模型线索，用户裁剪重新上传或手动添加。模型自由文本不作为事实展示，保留原始调用回执用于追溯。图中身份、体型、材质、保暖性均不属于分析目标。

确认线索与生成是两个独立动作。修改中的本地草稿必须先确认，再生成；旧版本冲突须明确核对后采用最新版本。允许移除全部线索，但空线索不能生成。再次分析须确认，成功才重置线索及确认状态；失败保留原值。运行中禁止编辑/删除，用户可取消。

生成使用当前可穿、持有、未删除、非示例单品，最多500件候选，冻结版本和偏好；发布时再校验。最多三套有不同主体组合的方案；仅换配饰不能凑数。每套至少含上装＋下装或连衣裙，同品类不能超过参考线索数量（未指定时最多一件）。缺少鞋包可形成明确标缺项的近似方案；不能用上装当下装，不能凭模型猜测候选品类“标错”。允许零方案。

结果分别展示接近的部分与缺少/无法核对的部分。后端按真实属性逐项匹配品类、颜色、风格；同一件衣服不重复填两个线索。层次不属于现有衣服属性，只作方向并明确无法确认实际叠穿。未知值不匹配为已知，不保证同款、复刻或合身。不提供购物链接。

结果使用现有不可变 OutfitRevision/OutfitImage，可进入历史、收藏、复用和实际穿着。独立创建生成来源会话，但不切换今日穿搭 current 指针。参考图方案不冒充今日天气推荐，天气明确未知；复用到普通搭配须重新核对条件。删除衣服或参考记录不改旧快照。

## API 与持久化

所有写请求携带 `Idempotency-Key`；JSON写请求还携带 `expected_version`。同键同负载回放原回执，同键不同内容409；更新与任务采用参考记录行锁。列表每页20条，`offset`分页。

| 操作 | 协议 |
|---|---|
| 上传 | `POST /references`，multipart `file`，201 ReferenceView；幂等内容绑定文件SHA-256 |
| 列表/详情 | `GET /references?offset=0`、`GET /references/{id}` |
| 衍生图 | `GET /references/{id}/image`，PNG、no-store；删除后404 |
| 分析 | `POST /references/{id}/analyze`，202 JobAccepted |
| 确认线索 | `PATCH /references/{id}`，`clues`数组及版本 |
| 生成 | `POST /references/{id}/generate`，202 JobAccepted |
| 删除 | `DELETE /references/{id}`，软删除、撤销读取与再次生成权限 |
| 状态/取消 | 复用 `GET /jobs/{id}`、`POST /jobs/{id}/cancel` 及事件协议 |

`ReferenceClue` 包含 `category`（已有词表）、`color_codes`（最多5）、`style_codes`（最多3）、`layer`（unknown/inner/outer/single），每次最多12条。分析含subject=single/multiple/unclear。ReferenceView含version、analysis、clues、confirmed、current_job_id、revision_ids、provider_mode和image_url。

新增 `outfit_references`：原件/衍生存储键、分析、已确认线索、版本、当前任务、最新结果ID、来源、创建和删除时间。迁移 `0015_reference` 仅新增表及索引；存在参考记录时阻止降级删除。历史结果通过 request_snapshot 保存 reference_id、reference_clues、reference_version、模型和提示版本，不依赖当前草稿。

`reference_analyze` 和 `reference_generate` 复用持久 Job、ModelCall、租约、心跳、取消、事件及 Langfuse。分析最多一次，生成最多两次（一次结构/领域失败纠正）；提交起五分钟总期限、单次120秒。已发送无回执时 interrupted，不自动重发；刷新/重连只读，显式新任务可能再次计费。任务结果、参考指针、快照与终态事件同事务提交。

分析复用 recognition_mode，生成复用 provider_mode；disabled不回退Fake。当前模型保持 qwen3-vl-plus，提示 reference-v2；配置变化拒绝旧待执行任务。官方接口预检依据：[视觉 OpenAI 兼容接口](https://www.alibabacloud.com/help/en/model-studio/qwen-vl-compatible-with-openai)、[结构化输出](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-structured-output)。JSON模式只保证结构方向，不能替代后端品类/真实性校验。

## 图片保留、恢复与限制

删除是软删除：撤销参考详情和图片URL访问，保留原件、衍生图、分析账本、来源关系及旧备份，不宣称永久擦除。当前没有自动媒体清理。保存的搭配使用独立衣服图片快照，不需要重新访问参考图。未来清理必须同时检查参考记录、任务和不可变来源引用。

新备份精确版本为 `0.7.9-reference` / `0015_reference`；包含已删除参考记录和其原件/衍生图，显式枚举 `reference-original` / `reference-display` 白名单目录，并验证结果及来源关系。旧版备份须使用匹配旧应用恢复；恢复后的旧任务全部中断，data_epoch清空旧客户端草稿和待发请求。

真实验收仅覆盖固定公开样例；不等于全部图片都准确。小样本、真实手机文件选择、真实HEIC原片与照片效果限制详见交付记录。P7.10不在本阶段实施。
