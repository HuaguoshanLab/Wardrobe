# 导入中的衣橱整理资料

实施计划与阶段状态见 [导入补齐计划](plans/import-organization.md)。本专题是新增字段的主要契约，替代 W1 初期排除导入的约定。仅图片与品类必填，不改变正式入库确认流程。

## I1 初始档案

`RowView.draft` 为 `ImportDraft`，兼容原基础属性，并增加以下可选字段。`PATCH /imports/{batch}/rows/{row}` 的 changes 可单独修改各字段，touched_fields 逐字段保护，包括明确清空。旧草稿读取时补默认值，无数据库结构迁移。

| 字段 | 含义/默认 |
|---|---|
| subtype_name | 子类名称，最多 40 字，未知 null；按当前品类精确匹配 |
| source | purchased/gift/other 或 null |
| acquired_on | 已发生的获得日期或 null，不能用录入日期代替 |
| price | 人民币非负精确十进制字符串，最多 8 位整数/2 位小数；null 与 0 不同 |
| condition | unknown（默认）/good/worn/needs_repair/damaged |
| fit | unknown（默认）/fits/unfit/not_applicable |
| storage | daily（默认）/stored，独立于可穿状态 |
| location | 收纳位置或 null，最多 120 字 |
| notes | 档案备注，默认空字符串，最多 2000 字 |

预览、查询、审核保存不会创建正式衣服或子类。确认入库时在原逐行事务内解析/创建同品类同名子类，停用子类阻塞该行并给出说明；并发确认依靠唯一键复用子类，不自动重新启用。初始资料拆到 Garment.lifecycle/subtype_id，不写入基础 Attributes。不凭导入资料虚构过去的维修、退出或穿着事件；后续实际动作继续走 W1。

审核页直接展示“分类与当前状况”和“获得与收纳资料”；未知不改成完好/合身，金额日期本地和后端双重校验。失败/版本冲突保留草稿，保存成功才关闭或进入下一件。已有导入确认幂等、人工字段优先、图片保留和已确认保护不变。

## I2 Excel v2

模板 meta.template_version 为 2，原 12 列顺序不变，后附 9 个可选列：子类、衣物状况、合身情况、获得来源、获得日期、购入金额（元）、收纳状态、收纳位置、档案备注。保留完整 v1 模板导入；旧数据缺少新字段时使用上述默认值。v2 列可以留空，不能删除或重排列头。

状况、合身、来源、收纳提供中文下拉值；解析接受中文显示值和对应协议值。获得日期支持真实 Excel 日期单元格或 YYYY-MM-DD 文本；金额按精确十进制验证。非法值按行标明中文字段名，在审核里修正/清空后可继续。公式和外部链接继续拒绝。Excel 导入不自动调用 AI，不自动覆盖已填资料。

## I3 视觉子类建议

识别响应 attributes 增加可选 subtype_name；旧响应缺少此字段仍有效。garment-vision-v5 请求携带按品类分组的候选名称（启用的已有子类加内置视觉名称），名称仅作数据、排列顺序不代表匹配程度。名称同义且视觉依据一致时复用已有子类，没有准确候选或无法确定时留空。模型必须同时提供品类，且子类精确属于本次该品类候选，后端校验失败不会合并。停用子类不会被自动重新启用。

视觉候选使用“夹克”等外形分类，排除“薄外套”“羽绒服”这两个无法仅凭照片确认薄厚/填充物的名称；不改动人工子类配置或既有单品。自定义候选仍需遵守未知事实边界，不凭名称猜测材质、实际用途或合身。

AI 子类仅预填草稿，正式子类仍在明确入库时解析。表格已有值、人工输入与明确清空优先；人工改品类时丢弃不相符的模型子类并提示核对。已确认单品不再合并识别结果。查询、刷新和重连不创建识别调用。

明显破损只在 uncertainties 中提示人工核对，不自动填写 condition；fit、获得日期、价格、来源、收纳、备注与整理决定均不属于模型输出。未确定的子类保留 null。目标数量、补充计划和换季进度仍在各自功能维护，不属于单件导入字段。

## 备份兼容

导入扩展本身不新增数据库迁移：W4 基线为 0010_seasonal，含 P7.1 的当前部署为 0011_manual_outfits；但草稿 JSON 扩展会使旧应用无法识别新字段，因此备份 app_version 更新为 `0.6.1-import`，格式版本仍为 1。延续项目严格同版恢复，不让含新草稿的包被 `0.6.0-p7.1` 误接受。升级前旧包保留；恢复旧包需先在匹配版本环境恢复再升级，不能改清单伪装版本。当前应用直接读取旧数据库草稿时补默认值，不回写历史或批量补成已核对。
