# P7.1 · 手动搭配与直接记录穿着

需求：P-34；顺序及范围见 [P7 计划](plans/P7-advanced.md)。实现已完成，部署与实际验证证据见 [开发记录](history/2026-10-30-p7-1.md)。

## 操作与保存

从“我的衣橱 → 手动搭配”或“穿搭记录 → 手动搭配 / 记穿着”进入；日历入口带入当前选中日期。搜索、品类、分页保留已选单品，支持 1～20 件，不要求凑齐套装。选择和编辑草稿保存在本机；关闭页面不会自动提交。

- 保存搭配：仅允许当前持有、非示例、未删除且可穿的真实单品；只进入历史，不写日历。
- 直接记录：实际日期为今天或过去，沿用 Asia/Shanghai 口径。暂不可用的单品必须明确确认当日确实穿过；保存不修改衣服可用性。
- 修改手动搭配：从详情打开，读取当前单品；保存为新 revision，原收藏、穿着记录和图像快照不变。失效单品保留提示，用户移除或重新核对后再保存。
- 收藏、复用、历史隐藏、穿着日期/备注编辑与删除复用已有接口。手动搭配只有显式“以这套为基础搭配”才建立当前会话；保存本身不切换首页。
- 不调用模型、不创建生成 Job，不自动锁定、生成或更改长期偏好。手动来源在历史卡片、详情及复用预览中标识。

界面布局、选衣核对和反馈规范见 [界面设计](design/UI.md#p71-手动搭配)，最新体验验证见 [UI 记录](history/2026-10-30-p7-1-ui.md)。

## API 契约

`POST /api/v1/manual-outfits` 必须提供 `Idempotency-Key`，成功返回 201 和 `{ revision, wear }`；保存搭配时 `wear=null`。

| 字段 | 语义 |
|---|---|
| `items` | 1～20 个 `{ garment_id, expected_version }`，ID 不重复，版本 ≥1 |
| `mode` | `save` 或 `wear` |
| `parent_revision_id` | 可选，只能引用已有手动快照；新版本保留父引用 |
| `worn_on` | `wear` 必填，不能是未来日期；`save` 不得填写 |
| `notes` | 最多 1000 字，穿着备注保存时去首尾空白；`save` 只能为空 |
| `acknowledged_unavailable_ids` | 必须恰好等于当前所选暂不可用单品的 ID 集合；`save` 为空 |

服务在同一事务中获取操作键锁、按 ID 顺序锁定单品、校验状态/版本和图片、写快照、可选穿着记录及回执。失败不遗留半套快照；相同键和负载返回原结果，换负载返回 409。新的独立键代表用户新操作，不合并两次独立记录。

前端在发出请求前持久保存原键和原负载。刷新不重发；结果不明只允许“重发同一操作”。明确 409/422 后可读取最新状态、保留备注/日期/选择、清除拒绝回执并重新确认。恢复备份触发 data_epoch 后沿用全局草稿清理。

状态不符、版本冲突或未确认不可用返回 409；格式、日期、数量、重复 ID 或不合法父来源返回 422。维护期间沿用全局写屏障。错误不会自动恢复可穿或静默删除选择。

## 快照和迁移

`OutfitRevision.source` 为 `generated | manual`。generated 的 `session_id/run_id/provider_mode` 非空；manual 三者全部为空，数据库 CHECK 约束强制。旧 API 快照未带 source 时前端默认 generated。AI 生成每批最多三套规则保持，手动每次只创建一个 revision。

迁移 `0011_manual_outfits` 在 `0010_seasonal` 后追加 source 默认 generated，并将三个来源字段改为可空；不改写旧 items、reason、日期或图片引用。已有手动快照时拒绝降级，不能通过删数据降级。共享 `services/outfits/snapshots.py` 冻结属性、标签名称和展示图片引用，删衣服不删历史图。

手动与 AI 穿着共用 WearRecord 和 W1 穿着摘要：同单品同日按一个穿着日计数，补记/改日/删除后重新计算；浏览、保存和收藏不算穿过。

## 备份与运行边界

备份应用版本为 `0.6.0-p7.1`，业务 revision 为 `0011_manual_outfits`。沿用精确版本恢复：升级前旧备份用于对应旧版本的回滚环境，不能直接导入新版本；新备份包含两种来源、父版本、收藏、穿着、幂等回执及图片。完整混合来源往返和旧快照迁移已在隔离 PostgreSQL 验证。

本轮有另一组导入/识别改动并行写入同一目录，发布使用 HEAD 基线叠加明确 P7.1 文件的冻结源码，独立数据库、卷、内部网络及 Fake Provider；没有把另一任务的未完成实现打包部署。源码清单、构建日志、备份和数据摘要在忽略目录 `data/acceptance/p7-1/`，不是版本库内容。

未包含：拖拽画布、图片合成、轮换、反馈和 P7.2～P7.10。Chromium 手机视口证据不代表 iOS/安卓真机验收。
