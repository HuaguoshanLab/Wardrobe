## 2. 第一项实现：真实照片识别

以下保留接续时的实现检查项；当前落地方案与验证结果以 [P6 识别](../P6-recognition.md) 为准，真实账号小样本证据见开发记录：

- 增加百炼视觉请求适配，传必要的标准衍生图，使用独立识别提示和严格属性输出 schema。接入时核对官方协议、账号地域、图像限制及结构化输出能力，不直接套用搭配的纯文本请求。
- 输出只允许识别属性；可见证据不足时留空，材质/厚度/保暖性不能凭外观当作已知。拒绝额外控制字段和伪造标签 ID；图片文字作为数据，不能成为系统指令。
- 为识别记录 job、行、步骤、尝试、模型配置及提示版本、发送状态和经校验响应；完成结果复用，已发送但响应未知不自动重发。现有 outfit_model_calls 保留，账本复用或新增方案在实现前写 ADR。
- 明确一批最多 20 张照片与现有每运行最多 4 次模型 HTTP 尝试的预算关系：按行建调用单元或调整批次调度；不能为每张图重置同一个 Job 的预算。实现选择同步 CONTRACTS 和测试。
- 明确行级 interrupted 与父批次汇总、显式重试及可能再次计费提示；不能让通用 AppError 捕获把未知调用静默降为普通失败。支持部分行继续人工确认。
- 保留 touched_fields、主动清空、已确认/移除行、租约和取消检查；模型调用不占用长数据库写事务。Excel 默认不识别，刷新/查询不调用模型。
- 识别与搭配分别展示能力和来源，保留 Fake/disabled；真实失败不降级成 Fake。更新 OpenAPI、生成类型和配置说明。
- 若增加表或字段，追加迁移，保留历史迁移与原账本；核对备份表清单、隔离验证、精确版本兼容和升级数据摘要，不默许旧备份跨版本覆盖。

完成门槛：模拟 HTTP 与真实 PostgreSQL 测试覆盖合法/非法输出、鉴权/限流/超时、未知响应、重复执行、取消、人工修改、批次部分失败与备份往返；随后独立记录真实账号结果。模拟通过仍不能标为真实识别已验。

## 4. 容量与磁盘不足方案

现有限额以 [P5](../P5.md) 为唯一依据。以下是测试设计；专用隔离配置、容量脚本与本轮执行结果见[容量验收记录](../history/2026-10-27-backup-capacity.md)。未覆盖项不能由本计划推定通过。

- 先记录宿主/容器内存、可用磁盘、数据行数、媒体数与字节量。合成数据只放隔离卷，独立记录 seed、生成方法和摘要。
- 分别测小样本、典型衣橱和接近限额；数据库 JSON、媒体文件数、压缩包大小和解压大小独立逼近边界，并分别测超限拒绝。不能只用高压缩率空文件代替照片负载。
- 记录导出、上传、隔离验证、恢复耗时，峰值内存、磁盘增长、维护持续时间；成功包逐项校验清单和引用。当前 JSON 导出在内存中组织，重点检查大库峰值。
- 磁盘不足通过有容量限制的隔离文件系统或可控 ENOSPC 注入实现，禁止填满宿主或业务卷。控制记录、导出、解包、恢复点、媒体预写分别覆盖；数据库存储不足另设隔离实验。
- 故障后检查原库/媒体摘要、维护是否可解除、控制器重启能否判定状态；不能只有 HTTP 失败断言。数据库切换后控制状态落盘失败也需覆盖。
- 覆盖恢复只在确认独立 Compose 项目、端口、数据库和卷后执行。P5 的 8099 隔离栈卷保留；复用前先检查，不假定为空。新建测试栈也不能沿用显式绑定的业务卷。
- 测试报告分别标明“合成负载”“真实规模”“故障注入”；进程退出或 ENOSPC 测试不能代表宿主断电/磁盘损坏已验。

## 5. 证据格式与交接

每次验收至少记录：日期、Git 提交及未提交差异、服务模式、数据库迁移版本、设备/客户端、样例摘要、A 编号、操作、预期/实际、Job/行/revision/restore ID、调用次数、耗时、结论、问题及复测记录。秘密和原始照片不提交仓库；脱敏结果与稳定的本地证据位置可记入开发记录。

状态使用：待实现、待外部条件、待执行、通过、失败。每次新增实现同步开发记录并执行相称检查；任何失败保持可追踪，不以“手工可用”掩盖已确认的 AI 识别功能缺失。
