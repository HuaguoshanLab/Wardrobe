## 1. 基线与交付方式

已检查的实现基线为 `a0ed311`：

- 搭配上下文读取天气、显式偏好和可用单品，没有读取实际穿着记录；超过 500 件可用单品明确拒绝。本阶段不顺带扩容候选系统。
- `WearRecord` 绑定不可变 revision，保存本地穿着日期与备注；同日同 revision 去重，允许同日多套，禁止未来实际穿着日期。
- 用户偏好是显式维护的业务数据；没有自动行为学习。反馈不会自动修改偏好或衣服属性。
- 普通搭配最多三套，指定替换必须保持全部非目标项；普通任务已有幂等、调用账本、中断恢复及 Langfuse 观测。
- 备份按精确表集合、迁移及版本校验，媒体引用需显式枚举。新增表或图片不能仅验证业务页面，遗漏恢复链路。

每项按以下闭环完成后，再进入下一项：

1. 固定本阶段行为、验收样例、字段和兼容策略，补充对应契约与决策。
2. 实现后端规则与必要迁移，再接前端完整流程；保留现有业务数据和用户修改。
3. 通过领域测试、真实 PostgreSQL 集成、前端类型/组件及隔离浏览器验证。
4. 按阶段完成真实模型效果验收；涉及新能力时先验证服务可用性，不能拿 Fake 成功冒充真实完成。
5. 验证升级、备份恢复及旧快照兼容；部署到本地应用并完成只读冒烟，记录证据和限制。

工程通过与真实效果通过分别记录。前置依赖或真实效果未通过的阶段标为未完成，不按“接口已接上”结项。用户已授权顺序实现，不为普通字段、文件拆分和测试反复请求批准；本轮“先出计划”不包含开始实现或真实模型调用。

## 3. P7.1 · 穿搭轮换（首先实施）

### 用户流程与默认口径

- 在现有搭配条件页增加“正常推荐 / 尽量避开近期组合 / 优先近期少穿”；默认正常推荐，旧会话和旧草稿按正常推荐读取。
- “避开近期组合”查看最近 7 个本地自然日（含当天）；“近期少穿”查看最近 30 个本地自然日（含当天）。首版固定窗口，不另做复杂设置页。
- 实际穿着是唯一统计来源；生成、收藏、浏览和选用不能算穿过。同一单品同一天出现在多条记录中，只计一个穿着日。
- 组合按真实单品 ID 的集合比较，不按 revision ID 或单品排列顺序；同时检查主体组合，防止仅换鞋包就被称为全新穿搭。上装/下装/裙装/外套的映射在领域规则中明确测试。
- 轮换是软目标，服从可用性、锁定、指定替换和本次要求；不把近期穿过的单品全部硬过滤。没有记录时说明依据不足，不能宣称“从未穿过”。
- 只换指定项时，模式仅影响可替换目标；其余项仍完整保持。鞋包允许重复使用，锁定导致重复时明确说明。
- 模式及统计依据进入已提交条件/任务快照；任务重放复用同一上下文。后续补记或删除穿着记录，只影响下一次显式生成。

### 实现顺序

1. 独立实现穿着聚合与组合签名规则，读取全量相关记录，避免只统计 API 第一页；对已删除单品保留历史统计依据，但不放回候选。
2. 扩展 Requirements、上下文及结果说明；同步 OpenAPI、前端生成类型、运行时 schema、条件草稿、复用和会话恢复。
3. 为模型提供有界统计摘要，后端独立评估重复/穿着天数，对合法结果排序并给事实说明；不能只加一句提示词就宣称轮换完成。
4. 新提示版本与旧持久任务分开处理；不为软目标另起无界模型循环，维持既有硬约束校验及调用预算。
5. 完成模式控件、结果依据与空记录/条件不足提示；不新增底部导航。

预期入口：`backend/app/services/outfits/context.py`、`backend/app/domain/`、`backend/app/schemas/profile.py`、模型适配与提交路径；前端 `features/profile`、`features/outfits` 和条件恢复逻辑。聚合按独立职责组织，后续统计复用，不能把数据库查询塞入纯领域层。

### 结束门槛

- 确定性样例覆盖：无记录、窗口边界、同日多套、同组合不同 revision、仅鞋包变化、补记/改日/删除、衣服软删除。
- 可替代组合存在时，预设合法候选中非重复/少穿方案排序优先；只有重复可行时保留可行方案并说明，不伪造“无解”。
- 锁定、指定替换、不可用、未知属性、三套上限全部保持；正常模式兼容旧流程。
- 刷新、重连、记录穿着和切换模式草稿均不调用模型；只有显式生成/调整创建任务。
- 固定衣橱下对照正常/轮换模式的真实样例，至少覆盖可轮换、锁定导致重复、少穿单品参与三类；记录候选、实际结果与额外调用次数。若真实模型持续忽略目标，修复本阶段，不跳到 P7.2。

## 4. P7.2 · 穿后反馈与明确偏好

### 完整范围

- 在实际穿着详情/记录面板增加可选结构化反馈：偏热、偏冷、舒适度、配色满意度及备注；可指向整套或该快照中的单品，允许修改、删除。
- 反馈绑定实际穿着记录，不改历史 revision，不将主观感受写成衣服客观属性。未记录穿着的搭配可调整，但不伪装成穿后反馈。
- 提供两个明确动作：“用于下次搭配”将可编辑文字加入条件草稿；“保存为长期偏好”先展示拟保存内容，用户明确保存后才生效。
- 首版通过确定性映射/可编辑文字处理反馈，无需为保存反馈增加模型调用。不能表达为已有偏好字段的内容进入显式备注，不偷偷改全局冷热倾向。
- 删除反馈不自动撤回用户另行保存的长期偏好；界面说明并提供偏好编辑入口。删除穿着记录时删除其附属反馈，保留独立偏好和搭配快照。

### 实现与结束门槛

- 新增反馈持久层和迁移，明确一条穿着记录的反馈唯一性、版本、幂等及单品归属校验；同步备份、维护屏障与恢复。
- “反馈已保存”和“偏好已保存”分别反馈；偏好保存失败不丢已保存反馈，重试使用原键和原负载。
- 测试跨记录目标拒绝、并发编辑、删除关系、重复保存、刷新恢复；验证记录反馈零模型调用、未确认零偏好写入。
- 验证明确保存后的偏好被下一次生成使用，本次要求仍可覆盖；旧搭配与旧反馈上下文不被重写。

## 5. P7.3 · 衣橱利用情况

### 完整范围

- 从“我的衣橱”进入利用情况子页；单品详情显示记录穿着天数、最近一次记录日期。
- 提供近 30 天、近 90 天、全部已记录时间三个范围；展示有记录单品占比、常穿单品及期间无记录单品。
- 复用 P7.1 的同单品同日去重口径。当前衣橱占比以未删除、非示例单品为分母，暂不可用仍属于衣橱；已删除衣服不混入当前库存分母。
- 文案为“记录穿着天数”“期间无记录”，不判断真实闲置。新入库单品显示入库日期，不能暗示已闲置整个窗口。
- 从单品发起“围绕这件搭配”只创建/预填明确条件与锁定，展示当前可用性；仍需点击生成，不因打开统计触发模型。

### 实现与结束门槛

- 后端只读聚合接口负责完整统计、排序和分页，前端不能累计第一页代替总量；优先数字与单品列表，不堆无用途图表。
- 验证同日去重、跨月边界、记录修改/删除、软删除衣服、空衣橱/零分母、新入库及多页数据。
- 用固定数据集核对精确结果；在隔离 500 件衣服及多页穿着记录数据上记录查询延迟和 SQL 数量，避免逐件查询。
- 浏览、筛选、刷新统计零模型调用；删除/补记后相关统计正确失效并刷新。

## 6. P7.4 · 旅行胶囊衣橱

### 首版范围

- 一个中国大陆目的地、1～7 个连续日期、每日主要场合；用户可指定必带单品和期望携带数量。
- 一次生成一个行程方案，每天一套，并给按真实单品 ID 去重的行李清单。多天计划采用独立结果协议，不放宽普通搭配最多三套的限制。
- 目标是在满足每日条件下减少携带件数，不承诺数学全局最优；鞋包可复用，上衣等重复穿着安排明确显示，可设置是否允许重复穿。
- 未来天气只使用对应日期有效预报；超出服务范围/未配置时支持用户填写或标为未知，不用今日实况代替。
- 允许调整某一天并固定其他天；替换后重新核算行李清单和携带目标。不可用/已删除的必带单品明确冲突。
- 计划独立保存版本与每日快照；行李可勾选已收拾，计划修改后的清单保留仍存在单品的勾选并标识新增项。
- 从“穿搭记录”进入独立旅行计划子页；实际穿着仍由用户在当天/过去日期显式确认，计划生成或日期到来不会自动写日历。

### 实现与结束门槛

- 新增行程、每日方案、行李状态与任务结果类型；独立规划工作流复用可用性/锁定规则，不通过连续点击普通生成拼凑行程。
- 任务设置整次行程预算、期限与中断语义；按天调整不重复生成其他天。部分失败只能标记不完整计划，保留此前可用版本。
- 测试 1/7 天边界、重叠日期、预报缺失、重复穿开关、件数不足、必带冲突、局部调整、幂等及进程中断。
- 验证行李清单精确去重、计划零实际穿着副作用、快照和新表完整备份恢复；真实模型完成三日与七日样例，逐日校验真实衣服和清单。

## 7. P7.5 · 参考图找衣橱内近似搭配

### 首版范围

- 一次上传一张参考图，显式点击分析后提取品类、配色、层次和可见风格线索，用户可修改/移除后点击生成。
- 分析与生成是两个明确动作。参考图不作为衣服导入，不创建已拥有单品；图中人物身份与体型不是识别目标。
- 先利用现有视觉能力和结构化衣橱属性，实际能力在本阶段预检。未标注属性保持未知，不假定已有视觉向量。
- 输出最多三套真实衣橱组合，区别展示“接近的部分”和“缺少的部分”；允许没有近似方案，不冒充同款或精确复刻。
- 首版不引入 pgvector、自动爬图或购物链接；只有样例证明确有检索瓶颈，才另记技术选型决策。

### 实现与结束门槛

- 独立参考图资源、分析任务、结构化可编辑草稿、来源引用与调用账本；接入已有媒体校验、任务恢复、观测和备份引用枚举。
- 删除参考记录不破坏已保存搭配快照；参考图保留/删除及备份中的存续关系有明确实现，不能只删 UI 入口。
- 至少覆盖清晰单人、遮挡、多人歧义、衣橱缺项四类样例；记录人工核对的可见属性准确性与组合贴近程度。
- 测试图片内指令不越权、未知属性、候选失效、分析失败、预算耗尽、幂等重发及刷新零调用。
- 真实图片分析与真实搭配均需通过；效果不足时保留失败证据并修正，不能用静态演示图结项。

## 8. P7.6 · AI 虚拟试穿

### 先验证能力，再接完整产品

- 现有 `qwen3-vl-plus` 的识别/搭配接入不能作为图像生成能力的证据。阶段启动时核实官方接口、账号权限、服装输入格式、地域、成本、超时与结果保存方式。
- 预检使用用户提供并明确用于试穿的照片及真实衣服图片；先固定模型、支持品类和真实调用上限，不擅自购买服务或上传未指定人物照片。
- 首版目标：一张人物照片＋一套固定搭配 → 一张试穿预览；生成范围应明确支持哪些品类，不支持整套时不能把单件演示标成整套完成。
- 单独展示“AI 试穿预览”，保留原始衣服图与搭配快照，明确不代表真实尺码/合身效果。生成图不得回写为衣服原图或识别事实。

### 完整产品与结束门槛

- 接入独立图像 Provider、资源与调用账本、任务进度、超时/取消/失败/显式重试；刷新不重生，外部调用状态未知时不盲目重发。
- 提交前明确展示会发送的人物照和衣服图；图片不进入普通日志/Langfuse 原始载荷，不包含凭据或多余元数据。
- 预览可保存、查看、删除；对人物原图、派生图、结果、备份副本的保留及删除边界给出准确说明。若旧备份仍保留照片，不声称删除已从所有副本抹除。
- 用约定样例逐项核对人物外观、衣服颜色、图案、版型及多件叠穿一致性，记录耗时与调用费用；工程成功不等于保真效果通过。
- 无可用服务、必要照片或效果不合格时，本阶段保持未完成并说明具体缺口；不发布假成功入口，不让其破坏已完成的 P7.1～P7.5。
