# W4 · 换季整理

状态：已实现、验证并部署；证据见 [W4 开发记录](history/2026-10-29-w4-seasonal.md)。

## 会话与核对

- `/api/v1/seasonal-sessions` 列表分页；POST 创建客户端 UUID 会话。选择季节、全部正式持有单品或该季节（包含季节未知）以及可选品类。建立固定范围及当时单品快照，不自动吸收后来新增衣服。
- 会话保存阶段（核对、目标、处理、总结）、逐件核对版本及待办。GET 只读；跨页修改后对比单品版本显示过期，目标以配置及规则依赖摘要判断过期。删除/退出仍保留原始范围记录。
- POST `/{id}/progress` 使用会话版本和幂等键；逐件核对带当前单品版本。保存进度不改变衣服。目标确认带当前目标 token，修改目标复用 W2 显式保存。
- POST `/{id}/actions` 展示并确认最多 20 件对象及具体动作后提交；每项有独立 action_id、单品版本与 W1 LifecycleInput。仅允许收纳、开始维修、明确保留和退出；退出仍使用 W3 全季影响 token。
- 批次在同一短事务中逐项 SAVEPOINT，单件校验失败不回滚其他成功项，也不伪装全批成功。批次幂等键绑定内容；成功 action_id 重放返回原结果。失败后读取最新状态，重新确认未成功项并使用新 action_id，禁止重复执行成功项。每项成功/失败回执持久化。衣橱锁在会话锁之前取得，与 W3 一致。
- 实际动作成功不自动清空用户待办。待办可能包含试穿、清洗等其他事项，需在核对页明确清空并保存；未清除内容继续计入总结的未解决项。
- 退出整理仅离开页面。服务器已保存的核对、待办、现实动作仍保留；尚未保存的表单有离开确认，可放弃。无隐式自动执行。

## 总结

- GET `/{id}` 返回最新盘点、核对覆盖、范围外新增数量和总结预览 token。POST `/{id}/complete` 需要当前会话版本、token 和明确确认遗留项。目标未确认或已核对项过期时拒绝完成；未核对/待办/已删除等计入未解决项，可明确保留至总结。
- 完成时在衣橱锁内重查，保存不可变 JSON 总结：统计时点、完整当季目标及四季版本、规则错误、数量 K/U/缺口、固定范围单品/图片快照、覆盖、待办、实际成功动作和失败回执。总结不触发任何动作，不自动购入/退出，也不调用模型。
- 已完成会话只读；再次整理创建新会话并重新选取当前范围与统计，沿用当前 W2 目标，不复制旧缺口。
- 新表 `seasonal_sessions`、`seasonal_items`、`seasonal_actions`；图片外键及已有媒体保守保留保证历史可读。迁移 `0010_seasonal`；备份严格版本 `0.5.0-w4`，完整包含会话/回执/总结。旧版本备份须使用对应旧应用恢复，不放宽版本校验。

## 界面与操作

- 整理记录先显示未完成项，历史总结折叠；分页数量只代表已加载记录。当前会话显示真实核对进度、资料变化和待办数量。
- 核对列表支持名称/待办搜索及待核对、已变化、有待办、全部分组，数量按本轮固定范围统计；查询参数保留筛选与搜索。未保存输入时阻止切换步骤与刷新，离开可选择继续编辑。前往单品资料、生命周期和目标编辑会携带本轮返回路径，刷新或保存后仍能回到原会话及筛选。
- 处理列表支持待办、最近未成功和已选分组，切换分组不丢失选择。对象及动作选择完成后打开独立确认面板；收纳/维修/保留与退出分组，退出仍逐件读取全季影响。
- 确认面板展示对象、动作、日期及退出影响；底部固定执行/返回按钮。每次打开需重新勾选，返回保留当前表单；失败保留原请求供显式重发，部分失败明确反馈成功与失败数量。
- 动作记录倒序显示成功/失败和具体动作；最近仍失败的单品可单独筛选。总结先显示关键数量，遗留项超过五项折叠；过期核对和未确认目标提供返回入口。保存总结仍受原有版本与确认约束。
- 样式沿用暖白/深绿、44px 操作控件、移动端底部面板与系统字体；浏览器验证和限制见 [W4 界面优化](history/2026-10-29-w4-ui.md)。
