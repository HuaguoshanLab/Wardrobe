# D-30 · P5 历史引用、维护屏障与数据格式备份

日期：2026-10-26。状态：工程实现，自动化验证见 [P5 记录](../history/2026-10-26-p5.md)。沿用 D-23 的维护态、独立恢复控制及确认令牌要求，不改变 P-18/P-19/P-20/P-23 的产品范围。

## 历史引用

历史隐藏元信息与内容快照分离，收藏/穿着引用固定版本。删除须处理所有复用版本的会话而非仅原会话；隐藏与新建复用会话通过 PostgreSQL advisory transaction lock 串行化，受影响会话行锁与活动任务检查阻止隐藏/生成竞态。收藏和同日穿着去重同时受事务锁与唯一约束保护。

## 维护与控制

本地 Docker 单机采用共享控制卷上的 flock 屏障。普通 API 请求和整个 worker 执行持共享锁；控制器记录维护意图后等待独占锁。覆盖检查点收尾而非只观察业务 Job 已终态。持久标记跨进程退出保留；独立控制器审计恢复后才放行。此方案依赖同一主机上正确支持 flock 的文件系统，不宣称支持跨主机分布式部署。

## 数据格式与事务切换

避免对用户上传的 pg_dump SQL 直接执行恢复。v1 ZIP 保存 JSON 行数据和媒体，数据库对象只能由本应用可信迁移/适配器初始化。PostgreSQL 负责数据类型、外键、唯一约束验证；隔离验证库不与业务库共享表。

媒体键不可变，恢复先写入缺少的媒体并校验，同名不同内容拒绝；旧文件不删除。数据库的两个 schema 在单个事务内恢复，只有提交后新引用才可见，因此进程失败时数据库自动回滚且原媒体仍有效。持久 new_epoch 在同一事务提交，解决“已提交但控制状态尚未写成功”的重启歧义。恢复前仍建立完整 recovery.zip，符合 D-23 的成对恢复点要求；不把数据库/文件系统称为同一个原子事务。

限制与复查条件：2 GiB 总包、128 MiB 数据库 JSON、10,000 文件；JSON 导出仍在内存中组织，较大衣橱需测量后演进为流式格式。无自动垃圾回收、备份清理和一键恢复点管理；支持版本精确匹配。服务认证、多人隔离、远程共享存储不在本阶段加入。
