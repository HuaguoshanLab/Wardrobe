# D-35 · 衣橱整理优先与可编辑盘点

日期：2026-10-29。状态：用户明确方向并依次授权 W1～W4；四阶段已实现、验证并部署，证据见 DEVELOPMENT。

## 新要求

用户关注单件衣服生命周期、四季所需数量、缺少/多余/新增/处理，并要求盘点表可自行修改，随后要求先生成计划。产品范围以 [PRODUCT](../PRODUCT.md) P-30～P-33 为准；细节、默认规则和验收在 [衣橱整理计划](../plans/wardrobe-organization.md)。

## 决策

- 当前优先序调整为 W1 生命周期 → W2 可编辑四季盘点 → W3 补充与处理 → W4 换季整理；原 P7 六项保留并顺延，不取消或改写其历史授权。
- 用户可改目标、需求分类、单品归类、整理决定与补充计划。实际数量由真实单品计算，不提供修改汇总数的第二份库存。
- 长期拥有、当前可穿、衣物状况及处理决定分开；待洗/收纳不等于缺少，待处理不等于退出。退出保留历史档案和图片。
- 未知属性独立待核对，不自动当作符合或不符合；数量目标以用户设置为准，可解释的估算只生成草稿，不冒充通用标准或自动覆盖。
- 盘点和整理使用业务规则，不依赖新增 AI 调用；不引入自动学习、购物链接或自动淘汰。

## 替换与边界

D-34 的“先做 P7.1”由本决策替换为“先做 W1”，其逐项完整交付原则保留。P-05 的原可穿/不可用业务语义保持，退出增加新候选硬约束，具体兼容字段已由 [W1](../W1.md) 补齐。最初规划仅文档，后续实施状态见下节。

计划中的字段、状态枚举、估算公式及页面位置为工程默认，不是已实现证据；每阶段须同步契约、迁移、备份恢复、必要测试和开发记录。

## 2026-10-29 · W1 实施约定

用户明确授权按计划实施 W1。状态资料独立于原 Attributes，以 JSONB 保存精确金额字符串等资料，ownership 与 subtype_id 独立列；事件仅追加。当前更正为关联原事件的日期/原因补充，不重放状态；误退出使用关联撤销。子类 W1 提供创建/选择/清空，预置词表、改名停用及盘点引用影响在 W2 完成。生命周期独立单品子页，原详情保留入口。实现和验证见 [W1](../W1.md)。

## 2026-10-29 · W2 实施约定

用户授权按计划继续 W2。四季配置按整季版本与幂等请求保存；需求 ID 稳定，删除保留软删除行，复制追加新 ID。采用完整衣橱的同事务快照，未知资料进入待核对，名称不参与分类；标签删除标记规则无效，不默默拓宽。子类停用保留现有引用，修改前核对影响令牌。日常轮换估算纯计算，显式采用到草稿，城市/收纳偏好只作背景。移动端复用原 UI 和公共面板，稳定 UUID 兼容局域网 HTTP。具体契约见 [W2](../W2.md)。
